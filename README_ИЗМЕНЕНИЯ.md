## Как посмотреть HTML на Windows

**Вариант 1: без клонирования всего репозитория.** Распакуйте ZIP, запустите `BUILD_SHANGHAI_PREVIEW.bat`. Скрипт с помощью Python скачает **только** оригинальные JSON и шаблон HTML из публичного GitHub по закреплённому коммиту и создаст `artifacts/tripwise-shanghai.html`, который откроется в браузере. Требуется интернет **только при первой сборке**. Готовая страница работает без интернета.

**Вариант 2: если репозиторий уже скачан.** Скопируйте содержимое ZIP поверх локального `TripWise` с сохранением папок, затем в корне проекта выполните:

```powershell
python scripts/build_shanghai_demo.py
node tests/test_shanghai_v2.cjs
python -m unittest discover -s tests -p "test_shanghai_builder_v2.py" -v
```

HTML появится в `artifacts/tripwise-shanghai.html`. Нужны Python 3 и (только для JS-тестов) Node.js. Зависимости Python не устанавливаются. **Если используется старый 46-объектный HTML, его нужно пересобрать** этой командой.

## Функциональность

- **100 POI** в итоговом HTML: 46 исходных + 54 полностью синтетических сценарных объекта из `data/demo/shanghai/pois-extra.json`. Все новые объекты открыто названы тестовыми; это не реальные музеи, кафе или аттракционы.
- **Главные и дополнительные интересы**: отмеченные категории оцениваются разными весами; каждый ещё непокрытый интерес получает повышенный приоритет. Если физически невозможно включить все интересы за выбранные дни, алгоритм вернёт `partial` и перечислит недостающие, а не заявит успешное покрытие.
- **Темп** влияет на продолжительность визита (спокойный 1,7×; сбалансированный 1,33×; насыщенный 0,95×) и верхний предел достопримечательностей в день (3/4/6). В типовом двухдневном сценарии сбалансированный план включает минимум два объекта в день. Внутренние события расписания идут подряд без `wait` и `rest`; заполнение абсолютно всего периода до выбранного конца дня не гарантируется, если нет подходящих вариантов.
- **Группа**: взрослые, дети, пожилые, питомцы; групповые тарифы и условные скидки (дети 50% на достопримечательности и 65% на питание; пожилые 70% и 90%). У конкретного объекта коэффициенты могут переопределяться. Неподходящие для питомцев объекты отфильтровываются (неизвестная pet-friendly политика трактуется консервативно).
- **Передвижение**: пешком, такси, общественный транспорт и смешанный вариант; короткие перемещения в смешанном режиме пешком, длинные — транспортом. Отдельные синтетические скорости, ожидания, тарифы, запас времени и правила поездки через реку. Переходов пешком через Хуанпу без настоящего моста алгоритм не придумывает.
- **Даты/сезонность/загрузка**: сезонные POI вне заданных месяцев исключаются, в сезон получают бонус; условно очень людные POI по выходным исключаются, если пользователь не пометил их обязательными. Для старых POI без метаданных сезон считается неограниченным **по гипотезе**, не по реальному расписанию.
- **Валюты**: CNY, RUB, USD, EUR, GBP; суммы вводятся в любой из них и переводятся в CNY перед расчётом. **Курсы фиксированные демонстрационные**, не текущие рыночные и не предназначены для настоящих платежей.
- **Наглядное HTML-объяснение**: приоритеты, состав группы, условия, реальные для данной анкеты выбранные места и их длительность, рассчитанные расходы и время поездок, условная схема точек.

## Что проверено

- `node tests/test_shanghai_v2.cjs`: 13 проверок пройдены.
- `python -m unittest discover -s tests -p 'test_shanghai_builder_v2.py' -v`: 1 smoke-test сборщика пройден на структурно эквивалентном минимальном шаблоне.
- 360 дополнительных детерминированных тестовых комбинаций: нарушений непрерывности **внутри показанного расписания**, часов и верхней границы бюджета не обнаружено. 88 `demo`, 133 `partial`, 139 `infeasible` — последние два результата при недостатке времени, разрешённых POI, бюджета или еды, это **не подтверждение хорошего маршрута**.
- Содержимое текущего удалённого шаблона сверено по всем 13 точным точкам подстановки. Сам итоговый HTML на настоящем шаблоне в этой среде не исполнялся: сетевой доступ контейнера к GitHub для скачивания исходных файлов отсутствовал. Требуется финальная проверка в браузере после сборки.

## Ограничения

Это экспериментальный JS-движок для браузера, **не продакшен ML**, не географический навигатор. Отсутствие окон достигается отказом от событий ожидания, а не подменой реального времени: при невозможности честно закрыть все условия будут предупреждения. Часы, тарифы, сезонность, толпы, доступность с питомцами и примерные маршруты смоделированы и требуют реальных данных перед выпуском продукта. Внешние API и платежи не подключались. Согласование архитектурного переноса в Python/backend — отдельная задача.
