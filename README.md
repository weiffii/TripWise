# TripWise — единое приложение

Учебный проект МАИ: персонализированное планирование туристических поездок. Ветка `feature/fullstack-unified` объединяет интерфейс и управление поездками из `feature/fullstack` с генератором, расписанием, картой и помощником из `integration/fullstack-ai-ds`. Исходные ветки сохраняются; `main` этим объединением не изменяется.

## Пользовательский сценарий

1. Изучить публичную главную. «Создать поездку» открывает регистрацию для гостя; после входа доступна анкета. Логотип TripWise ведёт на главную.
2. Выбрать Россию → Москву или Китай → Шанхай. Эти направления доступны первыми; остальные помечены «В разработке» и не запускают генерацию.
3. Указать местные даты и время прогулок, состав компании, бюджет, интересы, темп, транспорт и обязательные места. Основных интересов может быть от одного до всех восьми. Каталог обязательных мест использует ID выбранного движка, а не небольшой прежний справочник интерфейса.
4. Нажать «Создать маршрут»: генератор формирует временный результат с расписанием и картой. До кнопки сохранения карточка новой поездки в аккаунте не появляется.
5. На результате выбрать «Редактировать» либо «Сохранить поездку». Редактирование работает с временной копией; сохранённый оригинал меняется только после явного сохранения.
6. В «Моих поездках» можно открыть, редактировать или удалить выбранный сохранённый маршрут. Удаление требует подтверждения. Новая поездка не заменяет соседние записи. Прежние сохранённые анкеты остаются отдельным типом карточек и не выдаются за рассчитанные маршруты.

Светлая и тёмная темы сохраняются в браузере. Аккаунты и сохранённые поездки хранятся в SQLite. Изменение полей анкеты не вызывает автосохранения.

## Запуск на Mac

Нужны Python 3.11+ и Node.js 22+ в `PATH`. Node запускает существующий JS-движок Шанхая; FastAPI обслуживает единый сайт и API. Работайте из корня проекта.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8765
```

Первая команда создаёт окружение Python, вторая устанавливает зависимости, третья запускает сервер. Активация окружения необязательна, поскольку указан путь к его Python. Оставьте серверный терминал открытым. Адрес сайта: http://127.0.0.1:8765/ ; состояние: http://127.0.0.1:8765/api/health .

На текущем Mac Node также доступен в поставке приложения Codex. Если обычная команда `node` отсутствует, проверенный для этой установки путь можно добавить только для запуска сервера:

```sh
PATH="/Applications/ChatGPT.app/Contents/Resources/cua_node/bin:$PATH" .venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8765
```

Этот путь зависит от установки Codex и не заменяет требование Node на другом компьютере. Если порт занят, сначала найдите уже работающий сервер; не запускайте несколько копий на одном порту.

Используйте **один worker Uvicorn**: временные предпросмотры и диалоги помощника живут в памяти процесса. Несохранённый предпросмотр доступен до 60 минут в том же аккаунте и cookie-сеансе; перезапуск сервера или истечение срока требует повторного построения. Сохранённые маршруты остаются в SQLite.

## Запуск на Windows PowerShell

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Ограничения текущей генерации

- Доступны Москва и Шанхай, поездки на 1–5 календарных дней, не более 30 взрослых, 30 детей и 30 пожилых. Каждому дню нужен хотя бы час. Полные промежуточные дни планируются с 09:00 до 21:00; первый и последний ограничены временем из анкеты.
- Москва принимает бюджет в RUB. Шанхай принимает RUB/USD/EUR/CNY. Другие валюты могут оставаться в справочнике старых анкет, но не означают поддержку генератором. Неподдержанный параметр вызывает понятную ошибку, а не молчаливую замену.
- По согласованному решению от 22 ноября бюджет маршрута включает **питание, посещения/развлечения и местный транспорт**. Проживание и дорога до города не входят. Состав бюджета отличается от раннего этапа анкеты, где транспорт не учитывался.
- Для Шанхая существующий движок использует фиксированные учебные валютные коэффициенты. Это не актуальные рыночные курсы. Цены, условия посещения и часть исходных полей имеют учебный/оценочный характер; подписи и предупреждения результата не следует скрывать.
- Набор режимов транспорта передаётся движку явно. В этой версии автомобильный вариант интерфейса соответствует такси; он не обещает расчёт стоимости личного автомобиля.
- Расчётная линия и оценка длительности не становятся подтверждённой реальной навигацией от объединения веток. Онлайн-подложка требует сети, доступность внешних карт и сервисов проверяется отдельно. Есть офлайн-представление координат.
- Помощник использует существующие настройки и сервисы. Для внешнего LLM нужен `OPENROUTER_API_KEY` в окружении **до запуска**. Ключи не размещаются в браузере, URL и репозитории. Без внешнего ключа доступность локальных команд зависит от города и текущего сервиса; интерфейс показывает фактический статус. Платный LLM-вызов этим объединением не подтверждён.

## Хранение и совместимость

По умолчанию используется `runtime/tripwise.sqlite3`; папка `runtime/`, `.venv/` и `.env` исключены из Git. Не удаляйте базу, если хотите сохранить аккаунты и поездки. Для изолированных проверок задаётся `TRIPWISE_DB_PATH`; `.env` автоматически не загружается.

`users`, `sessions`, `auth_attempts` обслуживают аккаунты. `saved_trips` содержит прежние сохранённые анкеты с числовым id, `planned_trips` — рассчитанные маршруты с текстовым route_id и version. Это разные сущности. Прежняя миграция `multi-trips-v1` один раз переносит архив `trip_drafts`; повторный запуск не воссоздаёт удалённую мигрированную карточку. Изменения рабочего интерфейса не удаляют старые таблицы и данные.

Пароли хешируются scrypt со случайной солью; cookie-сеанс HttpOnly / SameSite=Lax. В БД хранится хеш токена, а не исходный токен. Проверяются принадлежность записей, Origin, контекст исходного владельца и версии там, где предусмотрено контрактом. Пароли и токены не сохраняются в localStorage. Нет подтверждения почты, восстановления пароля и отдельной приёмки публичного HTTPS-развёртывания; для учебного прогона используйте вымышленные данные.

## API и основные файлы

- `backend/main.py` — единый FastAPI, защищённые страницы и выдача frontend; внутренний корень репозитория не публикуется как статическая папка.
- `backend/accounts.py` — регистрация, вход, выход и сеансы; `/api/auth/`.
- `backend/catalog.py` — направления и справочники; `/api/catalog`.
- `backend/drafts.py`, `backend/trips.py` — совместимость и CRUD прежних анкет; `/api/trip-draft`, `/api/trips`.
- `backend/route_previews.py` — адаптер анкеты, временные результаты и явное сохранение. `POST /api/route-previews` строит без записи маршрута в SQLite; `GET /api/route-previews/{id}` читает свой preview; `POST /api/route-previews/{id}/save` с `{version}` сохраняет показанный результат. Повтор успешного сохранения того же preview не создаёт дубль.
- `POST /api/planned-trips/{route_id}/preview` с `{version}` создаёт временную копию своей сохранённой поездки. `DELETE /api/planned-trips/{route_id}` с `{version}` удаляет выбранную запись. Изменения требуют своего Origin и `X-TripWise-Draft-Owner`; несовпадающая версия не перезаписывается.
- `backend/shanghai.py`, `backend/moscow.py` — существующая интеграция генераторов, сохранённых маршрутов и помощника. Старый `POST /api/planned-trips` оставлен для совместимости и сразу строит/сохраняет; **новый интерфейс использует preview → save**. Это различие важно для тестов и внешних клиентов.
- `/api/planned-trips/catalog/{moscow|shanghai}` — реальные идентификаторы доступного каталога движка; `/api/planned-trips/{route_id}/assistant/` — существующий помощник. Подтверждённые правки preview остаются в памяти до Save.
- `frontend/questionnaire.js`, `trip-result.js`, `trips.js` и `backend/pages/` — анкета, результат и список; `/trip/new`, `/trip/result?preview=...` и `/trip/result?route=...`.
- `ai_ds/` — данные, подбор, построение и существующая логика помощника. Реализация алгоритмов не заменяется копией во frontend.

## Данные и источники

Проверяйте [правила источников](docs/ai/data-sources.md) и [AI/DS README](ai_ds/README.md). OSM-данные требуют атрибуции © OpenStreetMap contributors, ODbL 1.0; условия дополнительных источников фиксируются отдельно. Реальные, синтетические и оценочные данные различаются; внутренний TripWise Score не выдаётся за пользовательский рейтинг.

В репозитории сохранены прежние карты и отчёты Москвы/Шанхая в `artifacts/`, `reports/`, `data/demo/`. Они отражают конкретные снимки и этапы, а не доказывают актуальность каждого заведения, цены, часов работы или полноту глобального покрытия. Исторические московские отчёты о небольшом пилоте нельзя считать описанием всех возможностей нынешнего движка.

## Проверки

```sh
NO_PROXY=127.0.0.1,localhost no_proxy=127.0.0.1,localhost .venv/bin/python -W error::ResourceWarning -m unittest discover -s tests/fullstack -v
```

Тесты используют временные SQLite и свои порты. Нужна возможность открывать локальные порты. `-W error::ResourceWarning` делает утечки ресурсов ошибками; `-v` показывает отдельные проверки. Для тестов настоящего JS-движка Node должен быть в `PATH` так же, как при запуске сайта.

Прошли 67 серверных тестов, в том числе 9 проверок предпросмотра с управляемым генератором, и 20 тестов рекомендаций. Старый модуль `test_shanghai_integration.py` требует `httpx2` для установленной версии Starlette. В `test_moscow_v7_routing.py` три теста завершились ошибками и на объединённой ветке, и на исходном коммите `373aa1e` при одинаковых условиях.

Изолированный браузерный прогон с реальными движками подтвердил генерацию Москвы и Шанхая, отсутствие записи до сохранения, повторное сохранение без дубля, редактирование выбранной поездки и удаление с подтверждением. Также проверены переход по логотипу и смена темы при ширине 375 px. Внешняя сеть была заблокирована, поэтому проверка охватывает расписание и схему маршрута. Живой LLM и загрузка картографической подложки в прогон не входили.
