# TripWise

Учебный проект МАИ: персональные туристические маршруты. Ветка feature/fullstack содержит работу Участника 2 — Product и Fullstack Lead.

## Текущее состояние

Главная публично объясняет TripWise. «Создать поездку» открывает регистрацию в модальном окне для гостя, а после успешного входа — анкету. В шапке доступны отдельные вход и регистрация; авторизованному пользователю доступны поездки. Светлая/тёмная темы сохраняются в браузере.

Работают аккаунты, SQLite, «Мои поездки» и **несколько независимо сохраняемых анкет на аккаунт с редактированием и удалением**. Изменение полей больше не сохраняет данные автоматически. Анкета предлагает 7 стран / 8 городов, 16 обязательных мест, 155 валют (RUB/USD/EUR/CNY первыми), состав группы, даты/местное время, от одного до всех восьми основных интересов, транспорт и иллюстрированные карточки всех разделов. Логотип на трёх страницах ведёт на главную, кнопка «Создать новую поездку» в поездках видна постоянно. Это ограниченные справочники, а не весь мир или полноценный POI-набор алгоритма.

Генерация маршрута, его расписание, карта, Routing API и AI/DS ещё не подключены. Сохранённая анкета — параметры будущей поездки, не построенный маршрут. Для учебных проверок используйте вымышленные данные.

Код AI/DS напарника на стартовой проверке находился в отдельной ветке feature/ai-ds и ещё не объединён с этой веткой. Его нельзя считать автоматически подключённым. Требования и план не являются доказательством реализации.

## Запуск на Mac

Нужны установленный Python 3.11+ и терминал, открытый в корне проекта. Фактическая проверка выполнена на Python 3.13 / macOS arm64.

Первый запуск на новом компьютере:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Первая команда создаёт отдельное окружение Python в .venv. Вторая использует именно его Python и устанавливает версии библиотек из requirements.txt. Интернет нужен для скачивания библиотек. Активация окружения не обязательна, поскольку указан полный относительный путь к его Python.

При каждом запуске:

```sh
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8765
```

Оставьте терминал открытым. Адреса:

- http://127.0.0.1:8765/ — публичная главная, вход/регистрация в модальном окне.
- http://127.0.0.1:8765/api/health — ответ {"status":"ok","service":"TripWise"}.
- http://127.0.0.1:8765/trips — «Мои поездки», без входа перенаправляет на главную.
- http://127.0.0.1:8765/trip/new — новая пустая анкета, доступна после входа.
- http://127.0.0.1:8765/trip/new?id=ID — редактирование своей сохранённой анкеты с указанным ID.
- http://127.0.0.1:8765/api/trips — API списка своих сохранённых анкет.
- http://127.0.0.1:8765/api/catalog — публичный справочник направлений, мест и валют.
- http://127.0.0.1:8765/docs — интерактивное описание API. Для регистрации/входа используйте основную форму; POST-запросы требуют Origin того же сервера.

Uvicorn запускает объект app из backend/main.py. --host 127.0.0.1 оставляет сервер доступным только на этом компьютере, --port 8765 задаёт номер локального адреса. Сочетание Control+C останавливает сервер. После изменения Python-кода нужно остановить и запустить его заново. Если порт занят, остановите собственный прежний сервер либо выберите другой порт и используйте его в адресах; не завершайте неизвестные процессы.

Окружение уже создано на Mac Участника 2: повторная установка там не нужна, достаточно команды запуска. Двойной щелчок frontend/index.html открывает только внешний вид; для регистрации и входа открывайте HTTP-адрес запущенного сервера. Если после обновления интерфейс выглядит старым, обновите страницу в браузере.

## Аккаунты и база

При запуске создаётся runtime/tripwise.sqlite3: users, sessions, auth_attempts, saved_trips и schema_migrations. Старая trip_drafts сохраняется как архив. Миграция multi-trips-v1 один раз переносит старые черновики с прежними параметрами, владельцами и revision; повторный запуск не создаёт дубликаты и не восстанавливает удалённую мигрированную карточку. Рабочие данные теперь в saved_trips; прямые записи в старый архив после миграции не обновляют API.

Перед запуском обновлённого пользовательского сервера координатор сделал согласованную SQLite-копию через sqlite.backup: runtime/tripwise-before-multi-<time_ns>.sqlite3, права 0600. Содержимое не выводилось. runtime/ исключена из Git; резервная копия остаётся локальной. Затем сервер 8765 успешно прошёл startup с миграцией, /api/health вернул ok. Не удаляйте базу, если хотите сохранить аккаунты и анкеты. Для изолированных проверок задаётся TRIPWISE_DB_PATH; .env сам по себе не загружается.

Почта приводится к нижнему регистру, крайние пробелы удаляются. Поддержан ограниченный формат обычной ASCII-почты. Пароль регистрации — от 8 до 128 символов, повтор проверяется на сервере. Нет подтверждения владения почтой и восстановления пароля; не используйте этот локальный учебный вариант как публичный сервис с настоящими личными данными.

Пароли хешируются стандартным Python scrypt с отдельной случайной солью. В базе хранится хеш случайного токена сеанса, а сам токен передаётся в cookie HttpOnly / SameSite=Lax. Срок сеанса — семь суток; выход отзывает его на сервере. При повторном входе текущий токен заменяется. Сеансы на других устройствах сохраняются. JavaScript не хранит пароли или токены в localStorage.

Для POST-запросов требуется Origin, совпадающий с адресом сервера. Ограничение регистрации/входа — 30 попыток в минуту на IP. После превышения нужно подождать минуту. На локальном HTTP cookie работает без Secure; при прямом HTTPS-запросе добавляется Secure. Публичное размещение, HTTPS за прокси, распределённое ограничение попыток, рассылка почты и восстановление доступа требуют отдельной настройки и проверки.

API аккаунтов: POST /api/auth/register (email, password, password_confirmation), POST /api/auth/login (email, password), GET /api/auth/me, POST /api/auth/logout. Пользователь в ответе содержит только id и email. POST при работе из браузера посылается через fetch с JSON, а не через параметры URL.

## Проверка Fullstack

```sh
.venv/bin/python -m unittest discover -s tests/fullstack -v
```

unittest запускает тесты, discover находит их, -s задаёт папку, -v показывает каждую проверку. Тесты запускают собственный сервер на свободном порту и временную БД; не трогают вашу базу или уже работающий сервер. Нужна возможность открывать локальные сетевые порты.

В финальном независимом QA-прогоне 21 ноября **58/58 HTTP-тестов прошли**, 34.213 с, OK, без ResourceWarning. Использованы временные SQLite и собственные тестовые порты, с NO_PROXY и -W error::ResourceWarning. Проверены несколько анкет, изоляция пользователей, revision, Origin, создание без дублей, миграция, все 8 основных интересов и предыдущие регрессии каталога/дат/аккаунтов.

QA реально исполнил текущие questionnaire.js, destination-visuals.js и trips.js через Node VM с контролируемыми DOM/fetch — PASS. Проверены новый POST/редактирующий PUT, отсутствие автосохранения, правки во время запроса, повтор после потерянного ответа с тем же body/UUID, исправление данных после 422, все 8 интересов и Delete: отмена, ошибка, правильный id/revision/owner. Это клиентская логика с подставленными ответами, не native UI браузера.

Координатор в настоящем браузере на временной БД создал Париж со всеми 8 интересами и бюджетом 600, затем Токио 800. New открыл пустую форму. Edit изменил Париж на 650, Токио остался 800; обе карточки сохранились. Снимок на этом Mac: /tmp/tripwise-multiple-trips.png. Завершить подтверждение Delete в настоящем браузере не удалось: инструменты getJsDialog/close блокировались CDP timeout. Поэтому **браузерное удаление не объявляется проверенным**; API и JS-проверки прошли, остаётся вручную подтвердить отмену и удаление учебной карточки.

## Главная и анкета

Гость может изучить главную без аккаунта. «Создать поездку» открывает регистрацию; после успешной регистрации из этой кнопки сразу открывается анкета. Отдельный вход из шапки ведёт к поездкам. У авторизованного пользователя создание поездки открывает анкету напрямую.

Выберите страну, затем город: Москва, Санкт-Петербург, Париж, Рим, Стамбул, Токио, Пекин или Лондон. Время первой и последней прогулок вводится **по местному времени выбранного города**, не по часовому поясу компьютера. Сервер проверяет зону и отклоняет пропущенные/повторяющиеся часы при переводе часов. Введите количества взрослых, детей и пожилых, общий итог от 1 до 100, бюджет за поездку только на питание и развлечения, валюту, способ расчёта «на человека / на компанию», хотя бы один основной интерес (можно все восемь), дополнительные интересы без пересечения, темп и транспорт. Из небольшой подборки города можно выбрать несколько обязательных мест; при смене направления нужно подтвердить очистку прежних мест.

Валюты RUB/USD/EUR/CNY стоят первыми, далее другие коды по алфавиту. Выбор валюты **не пересчитывает сумму по курсу**. EUR 100 на человека для четырёх человек означает EUR 400 на компанию; скидки не рассчитываются. Все суммы принимаются с техническим пределом двух знаков после запятой, независимо от ISO minor_units: это бюджетная анкета, не платёжная система. Справочник валют — локальный снимок официального SIX, происхождение и политика отбора записаны в [backend-отчёте](docs/fullstack/agent-workflow/16_HOME_BACKEND.md). Каталог мест хранит реальные названия и ссылки, но не подтверждает цены, часы и маршруты.

**Изменения остаются в памяти вкладки до нажатия «Сохранить анкету».** Уход без сохранения не создаёт/обновляет серверную анкету; браузер предупреждает о несохранённых правках. Кнопка отправляет один снимок полей, дожидается успешного ответа и возвращает к карточке в «Моих поездках». Если во время запроса появились новые правки, они остаются несохранёнными и требуют отдельного нажатия. Ошибка не очищает поля и не сообщает успех. «Создать новую поездку» всегда открывает пустую форму и не меняет прежние анкеты. Каждое явное создание добавляет отдельную карточку. «Редактировать» открывает выбранный id, «Удалить» просит подтверждение и затрагивает только выбранную карточку. Пока это список сохранённых анкет, а не построенных маршрутов.

Кнопка темы доступна на трёх страницах. Сначала используется сохранённый выбор, иначе системная тема. localStorage хранит оформление; данные аккаунта и анкеты сохраняются через сервер. Старый черновик без состава получает техническое заполнение «все взрослые» — проверьте фактический состав; GET не переписывает запись и revision.

API коллекции: GET `/api/trips` возвращает owner_context и trips; GET `/api/trips/{id}` — свою запись. POST `/api/trips` принимает preferences и creation_key UUID; первый успех 201, повтор того же ключа/данных 200 с той же записью без дубля. PUT `/api/trips/{id}` принимает revision/preferences и увеличивает revision. DELETE `/api/trips/{id}` принимает JSON revision и отвечает 204. Все изменения требуют входа, своего Origin и X-TripWise-Draft-Owner исходной формы/списка. Владельца определяет только сеанс; чужой/отсутствующий id → 404, устаревшая revision → 409, отсутствующий контекст → 428, смена аккаунта → 409/ACCOUNT_CHANGED. Ошибки не очищают поля и не выдают чужие записи.

Старый GET/PUT `/api/trip-draft` оставлен только как адаптер к legacy-v1, а не к последней новой анкете. Поэтому старая открытая форма не может случайно изменить новую соседнюю карточку. После неясного сетевого результата создания клиент по отдельному повторному нажатию повторяет прежний снимок и UUID; после определённого422 исправленные данные можно отправить новым снимком. Автоматической досылки нет.

Новая `preferences.schema_version='fullstack-draft-0.2'` использует местные ISO datetime **без UTC-смещения** плюс IANA timezone города. Сервер проверяет связанную тройку страна/город/зона и DST. Старая `fullstack-draft-0.1` продолжает поддерживать московское aware-время. Деньги возвращаются десятичной строкой; состав `traveler_counts` должен суммироваться в travelers; required_poi_ids уникальны и принадлежат городу. Параметры Fullstack остаются отдельными от общего AI/DS-контракта.
