# TripWise — единое приложение

Один FastAPI обслуживает аккаунты, черновик Москвы и пилот Шанхая. В «Моих поездках» выберите «Спланировать Шанхай»: маршрут строится на сервере, сохраняется в SQLite и открывается повторно. Московская анкета не отправляется в шанхайский алгоритм.

Нужны Python 3.11+ и Node.js 22+ в `PATH`. Команды из корня проекта:

| Шаг | Windows PowerShell | macOS |
|---|---|---|
| Создать окружение | `py -m venv .venv` | `python3 -m venv .venv` |
| Установить зависимости | `.venv\Scripts\python.exe -m pip install -r requirements.txt` | `.venv/bin/python -m pip install -r requirements.txt` |
| Запустить | `.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8765` | `.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8765` |

Откройте `http://127.0.0.1:8765/`. Для ИИ-чата задайте `OPENROUTER_API_KEY` в окружении **до запуска**; без ключа маршрутизатор работает, а чат сообщает, что недоступен. Используйте один worker Uvicorn: диалог и неподтверждённые предложения живут в памяти процесса, а сохранённые маршруты — в SQLite. Подложка OSM требует сети; схема маршрута доступна офлайн.

Пилот использует существующий каталог из 5000 POI. Условия посещения, цены, курсы валют и часть POI учебные; отклонения и неполные маршруты отмечены в интерфейсе. Для Москвы нужен отдельный проверенный каталог и маршрутизатор, учитывающий её часы, географию и транспорт.

### API и проверка интеграции

- `POST /api/planned-trips` валидирует только шанхайскую анкету и строит маршрут через существующий `planTrip()`. Дневные окна — по времени `Asia/Shanghai`, бюджет на человека пересчитывается в бюджет компании по демонстрационному курсу.
- `GET /api/planned-trips` и `GET /api/planned-trips/{route_id}` возвращают только поездки текущего аккаунта. Исходная версия сохраняется при построении; новая версия — только после подтверждения предложения в чате.
- Под `/api/planned-trips/{route_id}/assistant/` доступны `GET status` и `POST register`, `message`, `decide`. Помощник берёт исходный маршрут из SQLite, не из браузера. Для записи используется Origin приложения, для чата — дополнительно `X-TripWise-CSRF`.
- Браузер показывает онлайн-подложку и оценочные пути, но приложение не использует переданные браузером времена OSRM для пересчёта расписания. Такой пересчёт остался в автономном Shanghai Lab.
- Тесты API: установите `httpx` в тестовое окружение и выполните `python -m unittest discover -s tests/fullstack`. Браузерный тест: установите `playwright` в то же окружение и выполните `python -m tests.fullstack.browser_shanghai` с установленным Chrome (или `TRIPWISE_BROWSER_CHANNEL=msedge` для Edge). Оба интеграционных сценария используют реальный JS-движок и временную SQLite; обращения к LLM заменены тестовыми ответами.
- Известная регрессия исходной ветки AI/DS: шесть проверок `tests/test_shanghai_synthetic_rebalance.py` ожидают старый набор из 2000 POI и не проходят на текущих 5000. Те же шесть падений воспроизводятся на неизменённом `feature/ai-ds`.

## Fullstack: аккаунты и анкета Москвы

Учебный проект МАИ: персональные туристические маршруты. Ветка feature/fullstack содержит работу Участника 2 — Product и Fullstack Lead.

## Текущее состояние

Работают регистрация, вход, выход, SQLite-хранилище аккаунтов, «Мои поездки» и анкета Москвы с автосохранением одного активного черновика на аккаунт. После регистрации вход выполняется автоматически. Анкета сохраняет даты/время прогулок, количества взрослых, детей и пожилых, бюджет в RUB/USD/EUR/CNY, интересы, темп и способы передвижения. На трёх экранах обновлено оформление с фотографией Москвы, светлой/тёмной темами и сохранением выбора темы. Маршрутизация Москвы пока не подключена. Для учебных проверок используйте вымышленные данные.

Описание ниже относится к московской анкете и аккаунтам; для пилота Шанхая используйте команды в начале README.

## Запуск на Mac

Нужны установленный Python 3.11+ и терминал, открытый в корне проекта. Фактическая проверка выполнена на Python 3.13 / macOS arm64.

Первый запуск на новом компьютере:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Первая команда создаёт отдельное окружение Python в .venv. Вторая использует именно его Python и устанавливает версии библиотек из requirements.txt. Интернет нужен для скачивания библиотек. Активация окружения не обязательна, поскольку указан полный относительный путь к его Python.

При каждом запуске:

```sh
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8765
```

Оставьте терминал открытым. Адреса:

- http://127.0.0.1:8765/ — интерфейс.
- http://127.0.0.1:8765/api/health — ответ {"status":"ok","service":"TripWise"}.
- http://127.0.0.1:8765/trips — «Мои поездки», без входа перенаправляет на форму.
- http://127.0.0.1:8765/trip/new — анкета Москвы, доступна после входа.
- http://127.0.0.1:8765/docs — интерактивное описание API. Для регистрации/входа используйте основную форму; POST-запросы требуют Origin того же сервера.

Uvicorn запускает объект app из backend/main.py. --host 127.0.0.1 оставляет сервер доступным только на этом компьютере, --port 8765 задаёт номер локального адреса. Сочетание Control+C останавливает сервер. После изменения Python-кода нужно остановить и запустить его заново. Если порт занят, остановите собственный прежний сервер либо выберите другой порт и используйте его в адресах; не завершайте неизвестные процессы.

Окружение уже создано на Mac Участника 2: повторная установка там не нужна, достаточно команды запуска. Двойной щелчок frontend/index.html открывает только внешний вид; для регистрации и входа открывайте HTTP-адрес запущенного сервера. Если после обновления интерфейс выглядит старым, обновите страницу в браузере.

## Аккаунты и база

При первом запуске создаётся runtime/tripwise.sqlite3 с таблицами users, sessions, auth_attempts и trip_drafts. Отсутствующая таблица черновиков добавляется автоматически, существующие аккаунты не удаляются. Папка runtime/ исключена из Git. Аккаунты, сеансы и черновик сохраняются после перезапуска. Не удаляйте базу, если хотите сохранить данные. Для изолированных проверок можно задать TRIPWISE_DB_PATH; .env сам по себе не загружается.

Почта приводится к нижнему регистру, крайние пробелы удаляются. Поддержан ограниченный формат обычной ASCII-почты. Пароль регистрации — от 8 до 128 символов, повтор проверяется на сервере. Нет подтверждения владения почтой и восстановления пароля; не используйте этот локальный учебный вариант как публичный сервис с настоящими личными данными.

Пароли хешируются стандартным Python scrypt с отдельной случайной солью. В базе хранится хеш случайного токена сеанса, а сам токен передаётся в cookie HttpOnly / SameSite=Lax. Срок сеанса — семь суток; выход отзывает его на сервере. При повторном входе текущий токен заменяется. Сеансы на других устройствах сохраняются. JavaScript не хранит пароли или токены в localStorage.

Для POST-запросов требуется Origin, совпадающий с адресом сервера. Ограничение регистрации/входа — 30 попыток в минуту на IP. После превышения нужно подождать минуту. На локальном HTTP cookie работает без Secure; при прямом HTTPS-запросе добавляется Secure. Публичное размещение, HTTPS за прокси, распределённое ограничение попыток, рассылка почты и восстановление доступа требуют отдельной настройки и проверки.

API аккаунтов: POST /api/auth/register (email, password, password_confirmation), POST /api/auth/login (email, password), GET /api/auth/me, POST /api/auth/logout. Пользователь в ответе содержит только id и email. POST при работе из браузера посылается через fetch с JSON, а не через параметры URL.

## Проверка Fullstack

```sh
.venv/bin/python -m unittest discover -s tests/fullstack -v
```

unittest запускает тесты, discover находит их, -s задаёт папку, -v показывает каждую проверку. Тесты запускают собственный сервер на свободном порту и временную БД; не трогают вашу базу или уже работающий сервер. Нужна возможность открывать локальные сетевые порты.

В независимом QA-прогоне 19 ноября прошли **39 HTTP-тестов** на временных SQLite и тестовых серверах: аккаунты, черновики, контекст владельца, валюты, состав и старые данные. Проверка выполнялась с `NO_PROXY=127.0.0.1,localhost no_proxy=127.0.0.1,localhost` и флагом `-W error::ResourceWarning`. Четыре JS-файла отдельно прошли синтаксический разбор через Node REPL / `vm.Script`; shell-команда `node` в среде была недоступна.

Координатор в настоящем браузере на временном сервере 8772 проверил регистрацию → «Мои поездки» → анкету → состав 2 взрослых + 1 ребёнок + 1 пожилой, EUR 100 на человека → EUR 400 на компанию → сохранение → возврат → повторное открытие с теми же значениями. При ширине 1440 проверены светлая/тёмная темы и сохранение выбора при переходах. На ширине 375 измерены `clientWidth=scrollWidth=375`, но снимок/отрисовка после изменения размера были ненадёжны, а попытки нажать переключатель темы не меняли DOM. Причина не установлена; полноценная ручная мобильная приёмка остаётся открытой. Отсутствие горизонтального переполнения по одному измерению не означает полного успеха мобильной версии.

Подробности: [занятие об оформлении и новых полях](docs/fullstack/LESSON_05_DESIGN.md), [независимый QA](docs/fullstack/agent-workflow/14_DESIGN_QA.md), [исправление и повторная проверка QA-01](docs/fullstack/agent-workflow/05_QA_RETEST.md). ## Анкета Москвы

Нажмите «Создать поездку» в «Моих поездках». Выберите начало первой и окончание последней прогулки по московскому времени. Введите отдельно количества взрослых, детей и пожилых; общий итог рассчитывается автоматически и должен быть от 1 до 100. Укажите бюджет за всю поездку (только питание и развлечения), валюту RUB/USD/EUR/CNY и способ расчёта «на человека / на компанию», 1–2 главных интереса, дополнительные интересы, темп и один или несколько способов передвижения. После корректного заполнения всех обязательных полей изменения сохраняются автоматически; дождитесь сообщения «Анкета сохранена в аккаунте». Незавершённое заполнение и ошибочные изменения не сохраняются. Браузер предупреждает о выходе при несохранённых правках.

Выбор валюты обозначает единицу введённой суммы, **не конвертирует деньги по курсу**. EUR 100 на человека для четырёх путешественников означает EUR 400 на компанию; детские и возрастные скидки не рассчитываются. Возрастные границы групп и влияние на алгоритм не утверждены. Старый черновик без состава получает техническое заполнение «все взрослые» — проверьте и исправьте его; это не сведения о фактическом возрасте старой группы. Чтение такого черновика не переписывает запись и её revision.

Кнопка темы доступна на входе, в «Моих поездках» и в анкете. Сначала используется сохранённый выбор, а если его нет — системная тема. Настройка оформления хранится только в этом браузере; данные анкеты проходят через сервер и SQLite.

«Готово — к моим поездкам» дожидается сохранения и возвращает к карточке черновика. «Продолжить анкету» восстанавливает параметры. Сейчас один аккаунт хранит одну активную анкету; это ещё не список готовых маршрутов. Список обязательных мест пока недоступен: нужен согласованный каталог реальных POI. Выбор транспорта и многодневность сохраняются как пожелания, не как подтверждённые возможности алгоритма.

API: GET /api/trip-draft возвращает owner_context и draft (текущий черновик или null). PUT /api/trip-draft принимает revision и preferences; требует входа, Origin того же сервера и заголовка X-TripWise-Draft-Owner с контекстом, полученным при загрузке именно этой формы. Контекст — предусловие совпадения аккаунта, а не разрешение выбрать владельца: запись по-прежнему принадлежит только пользователю серверного сеанса. Без заголовка возвращается 428 / CONTEXT_REQUIRED; при смене аккаунта — 409 / ACCOUNT_CHANGED, без изменения БД. Код ошибки находится в заголовке X-TripWise-Draft-Error. Обычный конфликт устаревшей revision остаётся 409 без этого кода и без перезаписи новых данных. Идентификатор preferences остаётся fullstack-draft-0.1; совместимое расширение добавляет traveler_counts (adults/children/seniors, сумма равна travelers) и четыре валюты. Контракт AI/DS не изменён. Передать user_id в теле запроса нельзя. Деньги сохраняются как точное десятичное значение, в JSON возвращаются строкой.

После смены аккаунта в другой вкладке автоматическое сохранение старой формы останавливается, её поля остаются на экране. Чтобы продолжить именно эту анкету, войдите в прежний аккаунт в другой вкладке и нажмите «Готово». При истечении сеанса также нужно войти в тот же аккаунт. Контекст не заменяется автоматически на нового пользователя. Обычный конфликт версий требует загрузки сохранённой версии; обновление страницы может потерять локальные несохранённые изменения. После обновления сервера старую страницу без нового контекста нужно обновить. Миграция базы не нужна.

## Проверка этапа 17 ноября

Точные результаты: docs/fullstack/LESSON_02_SERVER.md.

Эти 12 проверок относятся к предыдущему этапу первого сервера. Проверки аккаунтов описаны выше. Сквозной туристический сценарий и запуск с нуля на другом компьютере пока не проверены.
