# Анализ требований и постановка задач TripWise

## 1. Назначение

Этот скилл помогает анализировать идеи, формировать требования и превращать их в конкретные задачи для AI-агентов разработки TripWise.

Основной исполнитель — Analyst Agent.

Скилл применяется ко всей платформе, включая frontend, backend и Data Science & AI.

## 2. Когда использовать

- При обсуждении новых функций.
- Перед началом разработки компонента.
- При сравнении технических решений.
- Для подготовки промптов другим агентам.
- При распределении работы между несколькими агентами.
- При изменении требований.
- При планировании интеграции.
- При определении дальнейших шагов проекта.

## 3. Изучение контекста

Перед началом работы:

1. Изучи AGENTS.md.
2. Изучи актуальную документацию TripWise.
3. Проверь существующий код и структуру репозитория.
4. Определи уже реализованную функциональность.
5. Найди согласованные решения.
6. Уточни область ответственности по задаче.
7. Выдели ограничения, зависимости и неизвестные сведения.

Не придумывай содержимое недоступных файлов.

## 4. Анализ проблемы

Определи:

- какую проблему решаем;
- кому нужна функция;
- какой результат ожидается;
- какие требования уже утверждены;
- какие существуют ограничения;
- какие данные и инструменты необходимы;
- как проверить готовность результата.

Если задача сформулирована слишком широко, предложи её разделение.

## 5. Сравнение решений

Если возможны разные варианты:

1. Определи подходящие решения.
2. Сравни их преимущества.
3. Выяви недостатки.
4. Оцени сложность и риски.
5. Учитывай сроки и доступные ресурсы.
6. Проверь совместимость с архитектурой.
7. Порекомендуй наиболее обоснованный вариант.

Не выбирай технологию только из-за её популярности.

Объясняй причины рекомендации.

Окончательное решение остаётся за ответственными участниками команды.

## 6. Подготовка технического задания

Для согласованной функции опиши:

1. Цель задачи.
2. Пользовательский сценарий.
3. Функциональные требования.
4. Входные данные.
5. Выходные данные.
6. Ограничения.
7. Обработку ошибок.
8. Зависимости от других компонентов.
9. Критерии готовности.
10. Необходимые проверки.

Отделяй утверждённые требования от предложений.

## 7. Выбор агента

Определи профильного исполнителя:

- Data Agent — туристические данные.
- Recommendation Agent — рекомендации.
- Routing Agent — маршрутизация и Route Assistant.
- Ответственный за frontend — интерфейс; отдельный агент в текущей конфигурации не зарегистрирован.
- Ответственный за backend — серверная часть; отдельный агент в текущей конфигурации не зарегистрирован.
- Architect Agent — архитектура и контракты.
- QA Agent — проверка качества.

Если задача затрагивает несколько компонентов, раздели её на отдельные задания и укажи зависимости.

Не поручай двум агентам одновременное изменение одинаковых файлов.

## 8. Создание промпта для агента

Подготовь готовый к отправке промпт.

Промпт должен содержать:

### Контекст

Кратко опиши TripWise и конкретную задачу.

### Цель

Укажи, что именно нужно получить.

### Входные материалы

Перечисли существующие документы, данные и результаты предыдущих задач.

### Действия

Опиши последовательность выполнения.

### Разрешённые изменения

Укажи, с какими модулями и файлами разрешено работать.

Не выдумывай пути существующих файлов.

### Ограничения

Укажи, что запрещено менять и какие решения требуют согласования.

### Используемые скиллы

Рекомендуй подходящие скиллы из реально доступных в проекте.

### Критерии готовности

Опиши проверяемые условия завершения задачи.

### Проверки

Укажи необходимые автоматические и ручные тесты.

### Отчёт

Потребуй сведения об изменённых файлах, результатах проверок и оставшихся проблемах.

## 9. Передача работы между агентами

Если задача требует нескольких исполнителей:

1. Определи последовательность работы.
2. Подготовь отдельный промпт первому агенту.
3. Определи ожидаемый результат.
4. Укажи, что передать следующему агенту.
5. Подготовь следующий промпт с учётом результата предыдущего этапа.
6. Предусмотри независимую проверку.

Не объявляй передачу выполненной, если другой агент не получил результат.

## 10. Подготовка заданий для проверки

После реализации функции подготовь задание QA Agent.

Укажи:

- исходные требования;
- реализованную функциональность;
- затронутые файлы;
- ожидаемое поведение;
- позитивные сценарии;
- ошибочные и граничные случаи;
- критерии успешной проверки.

Не придумывай результаты тестирования.

## 11. Проверка готового задания

Перед передачей промпта убедись, что:

- исполнитель выбран правильно;
- задача сформулирована конкретно;
- требования не противоречат утверждённым решениям;
- указан ожидаемый результат;
- границы ответственности понятны;
- критерии готовности проверяемы;
- не требуется несогласованное изменение архитектуры;
- используемые скиллы действительно существуют либо явно обозначены как планируемые.

## 12. Формат результата

В зависимости от запроса предоставляй:

### Для анализа идеи

1. Описание проблемы.
2. Варианты решений.
3. Сравнение.
4. Рекомендацию.
5. Риски.
6. Вопросы для согласования.

### Для постановки задачи

1. Ответственный агент.
2. Готовый промпт.
3. Необходимые скиллы.
4. Критерии готовности.
5. Ожидаемые файлы и результаты.
6. Следующий этап.

### Для комплексной задачи

Подготовь последовательность отдельных заданий с понятной передачей результатов.

## 13. Ограничения

- Не изменять программный код.
- Не утверждать решения вместо участников.
- Не менять согласованные требования.
- Не выдумывать результаты исследований.
- Не создавать несуществующие технические зависимости.
- Не поручать агентам работу вне их ответственности без согласования.
- Не выдавать подготовленный промпт за выполненную задачу.
- Не передавать конфиденциальные данные.

## 14. Критерии завершения

Скилл применён успешно, если:

1. Изучен доступный контекст.
2. Определена цель.
3. Выявлены требования и ограничения.
4. Выбран подходящий исполнитель.
5. Подготовлено конкретное задание.
6. Указаны критерии готовности.
7. Определены необходимые проверки.
8. Указаны дальнейшие действия.

Все инструкции, объяснения и отчёты писать на русском языке.
