# TripWise — описание проекта

> Версия документа: 16 ноября 2026. Источник: согласованный единый план курсового проекта (3 ноября — 2 декабря 2026) и последующие решения команды об агентах. Этот документ описывает цели и обязанности, **не подтверждает фактическую реализацию**.

## 1. Суть продукта

**TripWise** (в раннем плане — Travel AI) — сайт для создания персонализированных туристических маршрутов. Пользователь указывает страну/город, даты, основные и дополнительные интересы, бюджет на питание и развлечения, темп, транспорт и обязательные места. Система рекомендует достопримечательности, распределяет их по дням, учитывает ограничения, показывает расписание и карту, позволяет редактировать и сохранять поездку.

**Проблема:** путешественник вынужден собирать сведения из разных источников, сверять часы работы, расстояния, бюджеты и реалистичность плана. Значимость этой проблемы должна подтверждаться интервью, а не предполагаться автоматически.

**Защита курсового:** 2 декабря 2026 года. **Внутренний дедлайн:** 1 декабря.

## 2. Пользовательский сценарий MVP

1. Открыть сайт и заполнить анкету поездки.
2. Получить подборку мест с учётом интересов, рейтингов, популярности и ограничений.
3. Получить поездку по дням с последовательностью посещений.
4. Просмотреть расписание и карту, ориентировочные затраты и предупреждения об неизвестных данных.
5. Для пешего режима видеть расстояния и время **по маршруту между соседними точками**, линию/карту и возможность открытия внешней навигации.
6. Изменить маршрут текстовым запросом через Route Assistant, проверить и подтвердить изменение.
7. Сохранить и повторно открыть поездку.
8. При стабильном MVP посмотреть **демо Premium** — краткий текстовый AI-гид для 3–5 мест и экран тарифа, без реальной оплаты.

## 3. Команда и зоны ответственности

### Участник 1 — AI & Data Science Lead

- Реальные POI-источники, нормализация, provenance и контроль качества туристических данных.
- Персонализированное ранжирование и объяснимые математические модели.
- Выбор мест, группировка по дням, оптимизация последовательности и проверка ограничений.
- Использование результатов реального маршрутизатора для оценки длительности пеших переходов.
- LLM-интеграция для редактирования маршрутов через Route Assistant и проверяемые функции.
- При стабильном MVP: проверенные факты и генерация коротких текстов Premium-гидов для 3–5 мест.
- Тесты интеллектуальных компонентов, объяснение алгоритмов на защите.

### Участник 2 — Product & Fullstack Lead

- Анкета пользователя, интерфейсы, карта и расписание.
- Backend/API, схема БД, сохранение и загрузка поездок.
- Подключение Routing API и вывод реальных пеших переходов, длительностей и расстояний, ссылок на внешние карты.
- Интерфейс текстового AI-редактирования и подтверждения изменений.
- При стабильном MVP: карточки AI-гида, отличие Free/Premium на уровне демонстрационного интерфейса.
- Интеграционные тесты, README, воспроизводимый запуск, демонстрация веб-сценария.

### Общее

Интервью и пользовательские тесты, архитектурные и JSON/API-контракты, взаимное ревью, GitHub Pull Requests, демонстрация реального собственного SKILL.md и стороннего MCP-вызова, презентация и защита. Ответственность за модули не подразумевает, что один участник выполняет работу другого.

## 4. Система агентов Codex

| Агент | Основной владелец | Роль |
|---|---|---|
| `data_agent` | AI/DS | Туристические данные |
| `recommendation_agent` | AI/DS | Рекомендации, математические модели |
| `routing_agent` | AI/DS | Оптимизация, Route Assistant |
| `frontend_agent` | Product/Fullstack | Интерфейс и карта (конфигурация напарника) |
| `backend_agent` | Product/Fullstack | API, база данных (конфигурация напарника) |
| `analyst` | Общий | Анализ требований и готовые задания агентам |
| `architect` | Общий | Архитектура, обмен данными и контракты |
| `qa_agent` | Общий | Функциональные и интеграционные проверки |

Согласованные скиллы: `data-poi-pipeline`, `data-poi-quality-check`, `recommendation-evaluation`, `route-validation`, `analyst-requirements`, `qa-integration-check`. **Наличие файлов и фактический запуск в Codex проверяются отдельно.** AI-агенты разработки и LLM внутри TripWise — разные системы.

## 5. Архитектурная схема

```text
Пользователь
    ↓
Frontend (анкета / карта / расписание / AI-редактирование)
    ↓
Backend/API ↔ База данных (поездки, пользователи при необходимости)
    ↓
AI/DS: POI → ранжирование → построение и проверка маршрута
    ↘ Route Assistant (LLM → разрешённые инструменты → повторная проверка)
    ↓
Backend → Frontend → подтверждение изменения / сохранение
```

Конкретные эндпоинты, файлы, схемы и технологии **нужно согласовать**, а не предполагать существующими. AI не выдумывает координаты, точное время проезда, расписания, цены и часы работы. Отсутствующие сведения маркируются.

## 6. Обязательные доказательства для курсового

- Рабочее приложение и README с воспроизводимым запуском.
- Репозиторий GitHub, доступный преподавателю.
- 3–5 исследовательских интервью и 3–5 пользовательских тестов (исходный план распределял первые интервью между двумя участниками).
- Хотя бы одна обнаруженная, исправленная и повторно проверенная проблема.
- Собственный `SKILL.md` с **реальным примером применения**; результаты раздельных агентных ролей.
- **Настоящий вызов стороннего MCP-сервера**: название инструмента, параметры, результат/снимок экрана.
- Презентация примерно на 5–6 слайдов, реальная демонстрация, вклад каждого, ограничения и перспективы.
- Указание применённых моделей, инструментов, значимых запросов и того, что люди проверили сами.

## 7. Правила командной работы

- У модуля один основной владелец; общий API-контракт меняется только по согласованию.
- Работа ведётся в feature-ветках, через небольшие PR и взаимное ревью.
- Проверка тестов и ревью обязательны перед признанием функции готовой.
- Синхронизация команды примерно каждые три дня, фиксация реального прогресса и блокеров.
- Не считать сгенерированный код готовой функцией без запуска и проверок.
- Если к 22 ноября основной сценарий нестабилен — **не добавлять новые функции**.
- После 26 ноября — **только исправления, тестирование и подготовка защиты**.
