# Реальные POI: OpenStreetMap / Overpass

Статус на 17 ноября 2026: адаптер загрузки и offline-нормализация реализованы; наличие фактически полученных наборов фиксируется ниже отдельно. Источник OSM согласован владельцем AI/DS. Контракт 0.1, ранжирование и маршрутизатор не изменяются.

## Объём

Загрузчик выполняет небольшие последовательные read-only запросы для Москвы (`RU-MOW`) и Санкт-Петербурга (`RU-SPE`). Запрос сначала получает административную relation с admin_level=4, затем использует её Overpass area. Это не отбор по одному bounding box. Выгрузка ограничена четырьмя группами: музеи/галереи, парки/сады/природные территории, кафе, смотровые площадки, до 12 исходных объектов на группу. Нормализатор выбирает до 24 структурно пригодных POI на город; равное покрытие восьми интересов не обещается.

Источники правил: [Overpass API и публичные серверы](https://wiki.openstreetmap.org/wiki/Overpass_API), [политика основного сервера](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html), [OSM: лицензия и атрибуция](https://www.openstreetmap.org/copyright). Небольшой snapshot не превращает публичный endpoint в production-backend с SLA.

Данные OSM распространяются под ODbL. Сохраняются исходный ответ, запрос, сведения о происхождении, ссылка на лицензию и атрибуция `© OpenStreetMap contributors`. При публикации и дальнейшем объединении баз необходимо соблюдать требования лицензии; внешние рейтинги не приписываются OSM.

## Запуск

Из корня проекта, Python 3.11+ и стандартная библиотека. Проверяемый интерпретатор текущего окружения — `C:/msys64/ucrt64/bin/python.exe`.

```powershell
& 'C:/msys64/ucrt64/bin/python.exe' -B -m ai_ds.sources.overpass --city moscow --attempts 1 --timeout 30
& 'C:/msys64/ucrt64/bin/python.exe' -B -m ai_ds.sources.overpass --city saint-petersburg --attempts 1 --timeout 30
```

Последовательно, не параллельно. По умолчанию основной endpoint — `https://overpass-api.de/api/interpreter`. Клиент задаёт идентифицирующий User-Agent; timeout по умолчанию 30 секунд, максимум 45; число попыток по умолчанию 2, максимум 3. `Retry-After` соблюдается, ожидание свыше 60 секунд прекращает загрузку. HTTP 400/403 не повторяются; 429/5xx и транспортные ошибки повторяются только в пределах указанного количества попыток. Размер ответа ограничен 8 MiB. HTTP timeout ограничивает socket-операцию, а не суммарную длительность DNS/всех сетевых стадий.

При недоступности основного сервера из-за timeout допускается явный выбор другого публичного сервера с предварительно проверенной политикой, например указанного в OSM wiki:

```powershell
& 'C:/msys64/ucrt64/bin/python.exe' -B -m ai_ds.sources.overpass --city moscow --endpoint https://overpass.private.coffee/api/interpreter --attempts 1 --timeout 45
```

Сменой endpoint нельзя обходить 403, 429 или ограничения среды исполнения. Ошибка sandbox требует разрешения на сетевой запуск, а не смены источника ради обхода.

При успехе CLI выводит новый каталог `data/raw/openstreetmap/<city>/<timestamp>/` с `response.json`, `query.overpassql`, `metadata.json`. Исходные байты ответа сохраняются без пересериализации; metadata включает SHA-256 ответа/запроса, время загрузки, endpoint, administrative relation, лицензию. Snapshot не перезаписывается.

Укажите фактический каталог, выведенный загрузчиком:

```powershell
$poiSnapshot = 'data/raw/openstreetmap/moscow/<фактический timestamp>'
& 'C:/msys64/ucrt64/bin/python.exe' -B -m ai_ds.normalize_pois --snapshot $poiSnapshot --limit 24 --output data/normalized/pois.openstreetmap.moscow.json --report reports/data/coverage.openstreetmap.moscow.json
& 'C:/msys64/ucrt64/bin/python.exe' -B -m ai_ds.data --input data/normalized/pois.openstreetmap.moscow.json --output data/processed/pois.openstreetmap.moscow.validated.json --report reports/data/poi-quality.openstreetmap.moscow.json
```

Для второго города заменить `moscow` на `saint-petersburg` и выбрать его реальный snapshot. Нормализация не обращается к сети. Она проверяет хеши, административные теги и соответствие сохранённого запроса утверждённому query. Существующие output/report защищены от случайной перезаписи; для намеренного обновления используется `--overwrite`.

## Нормализация и ограничения

- ID: `osm:<node|way|relation>:<id>`, внешний ID и source_url сохраняются.
- Имя: name:ru, иначе name. Категория — только явная таблица `data/mappings/osm_categories.v0.1.json`, не догадка по названию. `unusual` автоматически не назначается.
- Координаты node — исходные; для way/relation возможен bounding-box center. Его способ получения отражён в coverage и не считается подтверждённым входом для пешей навигации.
- `is_synthetic=false` используется только для реального snapshot. Искусственные ответы unit-тестов создаются в памяти/временных каталогах и не являются реальной базой.
- retrieved_at — загрузка, verified_at=null — факты отдельно не проверены.
- Рейтинг, популярность, цена и длительность неизвестны и остаются null; visit_duration_basis=null. Availability=unknown.
- opening_hours по контракту 0.1 остаётся null; исходные часы не теряются и доступны в raw.
- Объекты без имени, явной категории или пригодных координат не включаются в реальную демонстрационную выборку. Причины отражены в coverage.
- Повтор одного OSM ID в нескольких query-блоках объединяется только при полном совпадении записи. Конфликтующие варианты одного ID отклоняют обработку, а не выбираются молча.
- Source и synthetic/real не смешиваются. Дубликаты по похожему названию не объединяются автоматически.

Рекомендации могут работать по интересам при неизвестных рейтингах; это не закрывает полный F04 о качестве/популярности. Routing не может рассчитать посещения с неизвестной длительностью; нужны отдельно согласованные оценки и реальные времена переходов. POI-каталог не заменяет маршрутизирующий API.

## Проверки

```powershell
& 'C:/msys64/ucrt64/bin/python.exe' -B -m unittest discover -s tests -p 'test_poi*.py' -v
```

Проверяются mock-ответы, заголовки/timeout, 429/Retry-After, 400/403, ограниченные сетевые/5xx повторы, повреждённые ответы, remark, administrative relation, контрольные суммы, отсутствие snapshot при ошибке, категории, null, геометрия, дубли и детерминированный лимит. Фактический текущий результат — 21 OSM-тест успешно. Включены регрессии на положительный ID административной relation, целое ограниченное число попыток и явный timeout. Ошибки HTTP закрываются явно, ResourceWarning в повторном прогоне отсутствует.

## Рейтинги: отдельный следующий этап

При успешной загрузке `rating_matching_candidates` в coverage содержит до десяти реальных ID/названий/source_url для пилота сопоставления. Само сопоставление с другим каталогом и получение рейтингов не реализованы. Нужны утверждённый поставщик, API-доступ и проверка прав хранения/показа. Сведения второго источника нельзя записать в rating, оставив provenance только OSM. В текущем контракте один источник на набор; новая схема/overlay согласуется отдельно.

## Фактическая сеть

17 ноября обычный sandbox-запуск для обоих городов завершился WinError 10013. После отдельных разрешений выполнены загрузки основного endpoint для обоих городов: обе завершились `The read operation timed out`. Одна последующая попытка Москвы на публичном `overpass.private.coffee` (одна попытка, timeout 45) завершилась `Remote end closed connection without response`. Повтор резервного endpoint не выполнялся. Это не HTTP 403/429 и не попытка обхода квоты. Журнал: `reports/data/osm-download-attempts.2026-11-17.json`.

Реальный ответ, snapshot и нормализованные/проверенные OSM-наборы не получены. Количество реально принятых POI: **0**, но это результат сетевого блокера, не оценка покрытия OSM. Список 5–10 реальных объектов для рейтингового сопоставления не сформирован. Unit-fixtures не записывались в каталоги реальных данных. Следующий шаг — выполнить одну указанную команду в окружении с доступом к Overpass либо обработать подлинный snapshot, полученный тем же запросом. До успеха F03 остаётся незавершённой.
