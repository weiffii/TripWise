# Шанхай 5000: граница интеграции с Route Assistant

Дата: 19 ноября 2026. Это описание интерфейсов и оставшейся интеграции, а не заявление о работающем AI-редактировании HTML.

## Что сохранено

`ai_ds/route_assistant.py` не менялся. Его schema `0.2`, операции `replace_poi`, `add_poi`, `remove_poi`, `set_day_pace`, `set_meal_break`, предварительный просмотр и подтверждение с проверкой версии остаются действующими. Он повторно проверяет расписание через Python `multiday.schedule_sequences`.

Браузерный движок сохраняет синхронный `TripWiseShanghai.planTrip(dataset, options)` и schema `shanghai-demo-v1`. Worker меняет только способ запуска этой функции в демонстрации. Состав группы, бюджет, обязательные ID и полученные дорожные времена передаются заново при каждом расчёте. Каталог и пользовательские настройки не изменяются оптимизатором.

## Формат передачи партнёру

Нельзя передавать JS-результат в Python Assistant без преобразования: JS использует `days[].events`, Python ожидает `days[].visits` и отдельный routing context. Совпадающий ID объекта сам по себе не делает схемы совместимыми.

| Информация | Браузерная модель | Интеграционный контракт |
|---|---|---|
| Места и порядок | `days[].events`, типы `visit`/`meal`, `poi_id` | Упорядоченные ID по ISO-дате; питание сохраняется отдельным типом и окном |
| Время | Минуты от начала дня | Время с датой и часовым поясом Шанхая; без перестановки UTC и местного времени |
| Переходы | `from_poi_id`, `to_poi_id`, источник и buffered/base время | Направленные пары, транспорт, время отправления, provenance; прямую оценку нельзя превращать в подтверждённую дорогу |
| Деньги | CNY на всю группу и поездку | Тот же общий бюджет, цены группы, стоимость питания и транспорта |
| Защищённые места | `required_ids` | Сохраняются при правке, кроме явно подтверждённого удаления пользователем |
| Состояние | JS `demo`/`partial`/`infeasible` | Явное преобразование в Python-статусы; `demo` не означает реальные проверенные данные |
| Конкурентные правки | Worker request ID | Backend `route_id`, версия, POI snapshot, actor; ID запроса Worker не заменяет версию маршрута |

## Оставшаяся работа интеграции

1. Backend выбирает единый исполнитель расписания. Сейчас Python и браузерный JS — разные реализации, автоматического паритета нет.
2. Подготавливает адаптер снимка и направленных переходов с проверкой перечисленных единиц и происхождения.
3. Добавляет фиксированный пересчёт изменённой последовательности и окон питания; полный `planTrip` не является заменой такого пересчёта, поскольку может заново выбрать необязательные места.
4. Сохраняет существующие preview/confirm, авторизацию, версию и запрет подтверждения устаревшего preview. Не сохраняет неподтверждённый результат автоматически.
5. Проверяет замену, добавление, удаление, темп и окно еды на одном каталоге и одинаковых переходах с обеих сторон.

HTML позволяет менять анкету и обязательные места и полностью пересчитывать маршрут. Прямое текстовое AI-редактирование этого HTML и подключение к backend партнёра в этой поставке не реализованы. Действующий Python Assistant тестируется отдельно; успешные Python-тесты не подтверждают указанную интеграцию.
