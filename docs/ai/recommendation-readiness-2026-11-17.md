# Готовность рекомендаций TripWise — 17 ноября 2026

Статус: **baseline готов с ограничениями; полный F04 не выполнен**. Применён скилл `recommendation-evaluation`. Утверждённая модель `lexicographic-v0.1`, production-код, POI и контракт не изменялись. Работа выполнена по заданию Аналитика в рамках полного аудита AI/DS.

## Что проверено

Использованы последние реальные Geoapify snapshots: Москва `ru/20261117T173836.768006Z` (580), Санкт-Петербург `ru/20261117T173907.144035Z` (627), Токио `jp/20261117T173938.648464Z` (851), всего 2058 POI. Существующие шесть профилей и производные профили — тестовые сценарии, а не записи реальных туристов.

Создан [воспроизводимый evaluator](../../scripts/evaluate_recommendation_scenarios.py), который вызывает существующий `recommend` с фиксированным `evaluated_at=2026-11-17T21:00:00+00:00`; эта дата — контрольный параметр эксперимента, а не время фактического запуска. Он не обращается к сети и не меняет исходные записи. Результат: [JSON-отчёт](../../reports/recommendation/readiness-2026-11-17.json).

Для каждого города выполнены десять успешных сценариев: существующие museums/nature, природа+необычные места, развлечения+шопинг, только необычные места, нулевой бюджет при неизвестных ценах, смешанный набор городов, обязательное место вне top-K, пустой набор, неизвестный город. Дополнительно проверены три ошибки профиля на город: пустые основные категории, неизвестное обязательное место, обязательное место из другого города.

Всего **30 успешных сценариев, 204 проверки, 0 ошибок**. Сценарии подтверждают неизменность входов, уникальность ID, назначение города, устойчивость к обратному порядку входных POI, честные `not_checked`, отсутствие вымышленного score. Отдельно подтверждены обработка неизвестного города, сохранение обязательных ID и сообщения об ошибках.

| Профиль, каждый из трёх городов | Совпадение основной категории среди top-5 | Fallback |
|---|---:|---:|
| Существующий museums/history | 5 из 5 | 0 |
| Существующий nature/viewpoints | 5 из 5 | 0 |
| Тестовый nature/unusual | 5 из 5 | 0 |
| Тестовый entertainment/shopping | 5 из 5 | 0 |
| Тестовый unusual без дополнительных интересов | 0 из 5 | 5 |

Это техническое совпадение с категорией. Оно не измеряет полезность места, его качество, разнообразие внутри дня или пользовательскую релевантность. Для nature/unusual результат не доказывает поддержку unusual: совпадения обеспечиваются nature. В текущем Geoapify mapping unusual отсутствует. При таком запросе алгоритм возвращает объяснение `FALLBACK_SELECTION`, а не выдумывает подходящую категорию.

Нулевой бюджет не меняет top-5: `budget: not_checked` и `BUDGET_NOT_VERIFIED`. Это соответствует согласованной модели, но не означает соблюдение бюджета. Все рейтинги/популярность/verified_at неизвестны, поэтому при равных категориях порядок определяется ID. Срок загрузки не заменяет проверку фактов.

Обязательное место вне top-K сохраняется в отдельном `required_poi_ids`; оно не обязано появляться в `items`. Routing должен обработать оба поля и исходный POI-каталог. Порядок рекомендаций не является последовательностью посещений.
