# Чат редактирования Shanghai: интеграционный контракт

20 ноября 2026. Решение в пределах пользовательского задания на встроенный чат и минимальный локальный API. Этот документ фиксирует выбранную архитектуру; результаты проверок приводятся отдельно после реализации.

## Авторитетный механизм

Единственный исполнитель расписания пилота — JS `shanghai-engine.js`. Первоначальный маршрут по-прежнему строит `planTrip`; редактирование использует отдельный вход фиксированной последовательности в том же движке. Полный подбор `planTrip` не вызывается для небольшой правки.

Python `RouteAssistant` сохраняет хранение снимков, владельца, версию, fingerprint, предварительный просмотр, подтверждение/отклонение, срок действия и повторную валидацию. Адаптер явно преобразует браузерную `shanghai-demo-v1` в служебную `0.2`; это не две взаимозаменяемые схемы. Служебная оболочка хранит исходный native-маршрут, а окончательный результат возвращается в HTML в native-формате. Старый Python-маршрутизатор не подменяет JS-расписание.

JS вызывается локальным сервером через ограниченный JSON stdin/stdout протокол Node, без `shell=True`, `eval`, динамического пути к модулю или инструкций к ОС. Каталог читает доверенный серверный код, а не LLM. Веб-сервер использует стандартную библиотеку Python и расширяет существующий `serve_shanghai_demo.py`, сохраняя карту и её ограниченный tile proxy.

## Путь запроса

1. HTML строит обычный маршрут, затем регистрирует его компактный снимок и настройки в своей серверной сессии. Внутренний ranking на 5000 строк и весь каталог не отправляются.
2. Сообщение и ограниченный контекст текущей беседы поступают OpenRouter-интерпретатору. Он выдаёт только разрешённые структурированные операции или один уточняющий вопрос.
3. Код разрешает названия/ссылки на остановки и ищет кандидатов только в текущем каталоге. Применение нескольких операций — одна атомарная попытка.
4. JS проверяет варианты фиксированных последовательностей, общую стоимость, часы, группу, транспорт, обязательные места, повторы и интервалы питания 150/180 минут. Неизменённые дни сохраняются. Невыполнимая правка не меняет исходный маршрут.
5. API создаёт версионированное предложение. HTML показывает понятную разницу мест, времени, стоимости и дороги; оригинальное расписание и карта до подтверждения не заменяются.
6. По явному подтверждению выполняется повторная проверка. Только после успешного решения сервер возвращает новую native-версию для обновления карты, расписания и показателей. Отклонение сохраняет исходное состояние.

## HTTP и состояние

Предусмотрены status, register, message и decide под `/api/assistant/`. Точная форма сообщений и коды проверяются интеграционными тестами реализации. Сессия определяется серверной cookie; клиент не назначает себе actor/owner. Изменяющие запросы используют CSRF-токен, проверку локального origin/host, ограничение тела и строгую проверку полей. Внешнего CORS `*` нет.

Каждый подтверждённый маршрут имеет `route_id`, `version`, `poi_snapshot_id`. Предложение содержит `proposal_id`, `base_version`, срок действия, проверенное состояние и diff. Повтор запроса не должен повторно применять изменение; устаревшая версия или изменённые входные данные отклоняются. Повторное построение по анкете начинает новую регистрацию и делает прежний preview неактуальным для интерфейса.

Чат хранит ограниченную историю текущей сессии и последнее намерение/уточнение. Ответ «во второй» продолжает ранее заданный вопрос; последнее подтверждённое состояние является базой следующего изменения. LLM не выбирает цены и геометрию, не подтверждает свои предложения и не получает произвольных инструментов.

## Провайдер и отказоустойчивость

Используется существующий OpenRouter-интерпретатор, расширенный для текущего контракта; модель только `openrouter/free`, платных запасных моделей нет. Ключ читается сервером из `OPENROUTER_API_KEY`, никогда не помещается в HTML, сообщения API, журнал или файлы проекта. Передаются текущие остановки и ограниченный список кандидатов, а не 5000 POI. Mock LLM применяется только в явно обозначенных тестах, не как скрытая имитация рабочего агента.

При недоступности API/LLM обычный маршрутизатор продолжает работать. Открытый файлом HTML может показать план, но для чата требуется локальный сервер; он не обращается с ключом к LLM напрямую.

## Приёмка

Нужны unit-проверки разрешённых операций и фиксированного пересчёта, существующие регрессии маршрутизатора/Assistant/OpenRouter, API-тесты доступа и версий, multi-op/уточнения/последовательность сообщений, бюджет/закрытие/обязательные места, а также Chrome E2E: сообщение → реальный API → mock LLM → настоящий JS-пересчёт → preview без мутации → подтверждение → изменённые расписание и карта. Живые бесплатные запросы проверяются отдельно, если ключ доступен; их не подменяет mock-тест.
