# Рекомендательный baseline lexicographic-v0.1

Модель и область изменений утверждены владельцем AI/DS в чате. Реализация соответствует [контракту 0.1](contracts-v0.1.md); исходные POI и Data pipeline не изменены. Это порядок рекомендаций, не порядок посещения.

## Модель

Проверить профиль и весь набор POI. При структурной ошибке вернуть ошибку без частичной выдачи. Исключить другую страну/город и availability = unavailable. Неизвестную доступность допускать с предупреждением. Город сравнивается после удаления крайних пробелов и casefold, без геокодирования.

Ключ сортировки по убыванию, слева направо:

1. Число совпадений основных интересов.
2. Число совпадений дополнительных интересов.
3. Наличие рейтинга, затем (value − scale_min) / (scale_max − scale_min).
4. Наличие сопоставимой популярности, затем её значение.
5. Наличие допустимой verified_at, затем более поздняя дата.

При полном равенстве — ID по возрастанию. Численных весов нет; порядок критериев является настройкой модели. score = null. Наличие признака отделено от его значения: неизвестное не записывается нулём в POI или ответ. Известный низкий рейтинг выше неизвестного при равенстве интересов — консервативное правило, которое может занижать новые места.

Популярность используется только при одной metric среди кандидатов; иначе отключена для всего запроса с предупреждением. Смешивание источников запрещено уже Data pipeline. Разные шкалы рейтинга линейно нормализуются; статистическая сопоставимость не доказана, о допущении возвращается предупреждение.

Линейная формула рейтинга вычисляется через стандартный Fraction: это сохраняет формулу и точное отношение входных чисел без переполнения разности крайних float (например, шкалы [-1e308, 1e308]). Производное значение остаётся внутренним ключом и не сериализуется в ответ.

Актуальность использует verified_at, не retrieved_at. Будущая дата не даёт преимущества. Внутренний параметр recommend(..., evaluated_at=...) принимает datetime с часовым поясом для воспроизводимых тестов. По умолчанию используется текущий UTC. Все текущие синтетические POI имеют verified_at = null; влияние даты проверено отдельными синтетическими тестовыми примерами, не реальными фактами.

Временные моменты сравниваются точными целочисленными ключами микросекунд с учётом смещения UTC. Это сохраняет порядок и точность микросекунд, включая даты, для которых преобразование в UTC datetime вышло бы за диапазон лет 1–9999.

Обязательные ID сохраняются независимо от top-K. Неизвестный ID даёт UNKNOWN_REQUIRED_POI, недоступное обязательное место или место вне выбранного города — REQUIRED_POI_CONFLICT. Общий ответ ошибки имеет code = VALIDATION_ERROR и details с кодами причин.

Бюджет, даты, темп и транспорт валидируются, но не влияют на ранжирование 0.1. Бюджет, часы работы и маршрут имеют статус not_checked. Координаты могут отсутствовать, что отмечается предупреждением. Наличие reason-кода показывает участие признака в ключе, а не доказательство, что именно он определил итоговую позицию.

## Файлы

- ai_ds/recommendation.py — validate_preferences, recommend, RecommendationError.
- ai_ds/demo.py — CLI, JSON-ответ в stdout, ошибки в stderr.
- examples/preferences/history.json и nature.json — два синтетических профиля.
- tests/test_recommendation.py — 18 тестов, включая независимые ожидаемые порядки и регрессии QA.

Вход recommend — профиль UserPreferences и массив POI; выход — Recommendation. Функция повторно проверяет набор через process_pois, но не меняет вход. Routing получает полный проверенный набор отдельно от top-K.

## Команды запуска

Из корня проекта на Python 3.11+ со стандартной библиотекой и доступной базой часовых поясов:

```powershell
python -B -m ai_ds.demo --pois data/processed/pois.synthetic.validated.json --preferences examples/preferences/history.json
python -B -m ai_ds.demo --pois data/processed/pois.synthetic.validated.json --preferences examples/preferences/nature.json
python -B -m unittest discover -s tests -v
```

Проверено уже установленным интерпретатором Python 3.14.5:

```powershell
& 'C:/msys64/ucrt64/bin/python.exe' -B -m ai_ds.demo --pois data/processed/pois.synthetic.validated.json --preferences examples/preferences/history.json
& 'C:/msys64/ucrt64/bin/python.exe' -B -m ai_ds.demo --pois data/processed/pois.synthetic.validated.json --preferences examples/preferences/nature.json
& 'C:/msys64/ucrt64/bin/python.exe' -B -m unittest discover -s tests -v
```

pytest в этом интерпретаторе не найден; ничего не устанавливалось. Если zoneinfo не может разрешить название часового пояса, профиль отклоняется с TIMEZONE_UNAVAILABLE; установка базы требует отдельного решения. CLI: 0 — успех, 1 — ошибка валидации, 2 — ошибка чтения/JSON/обработки входа.

CLI явно настраивает stdout и stderr на UTF-8. Байтовый subprocess-тест проверяет успешный ответ с кириллическим ID и оба типа ошибок при PYTHONIOENCODING=cp1251 и PYTHONUTF8=0.

## Фактические результаты

После согласованных исправлений QA прошли 36 тестов: 18 Data и 18 Recommendation. Проверены основные и дополнительные интересы, рейтинг и шкалы, популярность и разные метрики, пропуски, свежесть и будущие даты, пустой набор, неверные профили, обязательные места, город, равенства, перестановка входа, неизменность данных, объяснения и CLI. Новые регрессии проверяют крайние шкалы рейтинга, крайние даты и эквивалентные смещения с точностью микросекунд, реальные UTF-8 байты stdout/stderr при cp1251.

Оба CLI-запуска завершились кодом 0. Top-5:

| Профиль | ID по порядку |
|---|---|
| history | synthetic:museums-01; synthetic:museums-09; synthetic:history-02; synthetic:history-10; synthetic:nature-03 |
| nature | synthetic:unusual-08; synthetic:nature-03; synthetic:nature-11; synthetic:museums-09; synthetic:museums-01 |

Это проверка согласованных правил, а не пользовательской релевантности. Precision/Recall/NDCG не рассчитывались: разметки нет. Количественный эксперимент с неперсонализированным baseline не проводился.

## Исправление кодировки Data и профилей

QA подтвердил повреждение русских подписей в синтетических fixtures. По отдельному согласованию Data Agent восстановил названия и город, не меняя ID и числовые признаки. В обоих демонстрационных профилях восстановлено destination.city = «Тестовый город». Проверки фильтра города не отключались; оба ожидаемых top-5 сохранились.

Текущие профили применимы только к синтетическому набору, не к реальному городу. Модель и контракт не изменены.

Реальные данные, проверка бюджета/часов/маршрута, маршрутизатор, HTTP-интеграция и пользовательская оценка остаются вне выполненного этапа. TASKS.md и общий контракт не изменены.
