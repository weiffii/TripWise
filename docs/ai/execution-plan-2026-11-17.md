# TripWise — согласованный пакет работ на 17 ноября 2026

Основание: владелец AI/DS согласовал пакет на 4–6 часов, только бесплатные источники и готовность получить бесплатный API-ключ. Готовый код используется повторно. [Материалы интервью](../research/interview-results-2026-11-17.md).

## Исходное состояние

Есть Data pipeline, lexicographic-v0.1, однодневный Routing, synthetic demo и 77 ранее подтверждённых тестов. Это исторический результат, не новый прогон текущей задачи. Реальных POI по последнему журналу нет.

Используются существующие документы: [источники](data-sources.md), [контракт](contracts-v0.1.md), [Routing](routing-contract-v0.1.md), [backend](backend-integration.md), [демо](demo-runbook.md).

## Порядок работ

| Этап | Владелец | Вход | Критерий готовности |
|---|---|---|---|
| 1 | Analyst | Ответы R1–R3 | Обезличенные протоколы, пропуски и наблюдения; без вымышленных ответов |
| 2 | Data | Источники и контракт | Официальные условия/поля проверены, один источник выбран с владельцем, доступ проверен |
| 3 | Data | Утверждённый источник и доступ | Настоящие ID/provenance, raw, нормализация, отчёт качества, тесты и фактический объём |
| 4 | QA | Новые результаты Data | Проверены источник, UTF-8, категории, null, дубли и совместимость |
| 5 | Architect/Routing | Контракт и ограничения данных | Предложены 1–3 дня и три темпа; модель и параметры представлены человеку |
| 6 | Analyst/QA | Принятые результаты | Команды демо, актуальные ограничения и пакет передачи напарнику |

Сначала цель 20–30 пригодных POI на город. После успешной загрузки — ориентир 50–100 для Москвы, Санкт-Петербурга и одного зарубежного города, например Токио. Это не гарантия покрытия. Источник, расходы и точные изменения утверждаются до подключения.

## Задание Data Agent

Применить data-poi-pipeline и data-poi-quality-check. Изучить AGENTS, четыре основных docs, data-sources.md и готовый pipeline. Проверить Geoapify/OpenTripMap/Foursquare OS по официальным условиям: доступ, бесплатные лимиты, лицензия, хранение, атрибуция, поля и города. Не повторять неудачные Overpass-запросы без нового основания.

Представить один источник и точные пути адаптера, затем получить согласование владельца. После выбора реализовать только утверждённый адаптер/нормализацию/тесты, переиспользуя валидацию. Реальные неизвестные рейтинг, популярность, цена и длительность — null. Часы в контракте 0.1 — null; исходные сведения сохраняются raw в рамках лицензии. Не смешивать источники и не менять Recommendation/Routing или контракт.

Ключ не публиковать. Никаких платных запросов, регистрации за пользователя и зависимостей без решения владельца.

Результат: raw provenance, проверенный набор, отчёт качества/покрытия, количество принятых/отклонённых, команды и результаты тестов. При недоступном API — blocker без fake real output. Передать ограничения QA и Routing.

## Задание Architect / Routing Agent

Использовать текущие интерфейсы и данные; не создавать backend-spec заново. Подготовить отдельное предложение для 1–3 дней и трёх темпов: входы, дневные окна, отдых, обязательные места, неизвестные длительности/цены/часы/переходы, целевая функция, предел сложности и контрольные примеры.

Сравнить простые варианты, объяснить параметры. Сейчас не менять код и действующий контракт. Реализация — после утверждения конкретной модели. Реальная пешая навигация требует подтверждённого провайдера, тестовая матрица её не заменяет.

## Задание QA Agent

Применить qa-integration-check, recommendation-evaluation и route-validation по назначению. Не менять код/данные. Проверить новый результат Data и связанные риски, затем необходимую регрессию.

Проверить ID, координаты, категории, null, дубли, лицензию/provenance, UTF-8 и раздельность synthetic/real. Использовать готовые demo-команды. Зафиксировать команды, результаты, ошибки и непроверенное. Получение POI не считать выполнимым маршрутом при неизвестных длительностях и переходах.

Все исполнители работают в общей кодовой базе: у файлов один владелец, чужие изменения не отменять. Параллельно выполняются только независимые этапы.

## Что не утверждено этим пакетом

Новые математические модели и API-контракты, платные сервисы, расходы, зависимости, scraping Tripadvisor, смешивание источников рейтингов, запись ключей в Git, полный ОТ, погода, совместность, Premium и изменения Fullstack.

LLM-интеграция требует выбора доступного API и проверенного вызова. Бесплатный чат не подтверждает API-доступ.

## Итог дня

Обязательный результат: протоколы интервью, проверяемый источник/доступ, по возможности настоящий набор и отчёт, рекомендации с объяснениями, воспроизводимое демо, тесты и ограничения.

При сетевом/ключевом блокере явно фиксируется незавершённость данных. Дополнительный результат по времени — утверждённое расширение Routing; все новые функции одновременно не обещаются. Commit/push этим аналитическим этапом не выполняются.
