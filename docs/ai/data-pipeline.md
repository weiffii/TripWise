# Локальный POI pipeline 0.1

Реализация по [контракту](contracts-v0.1.md). Сетевых запросов нет, сторонние зависимости не требуются. Синтетический набор проверяет поведение кода и не закрывает F03 о реальных источниках POI.

## Запуск

Из корня проекта, Python 3.11+:

```powershell
python -B -m ai_ds.data --input data/fixtures/pois.synthetic.json --output data/processed/pois.synthetic.validated.json --report reports/data/poi-quality.synthetic.json
python -B -m unittest discover -s tests -v
```

При существующих выходных файлах первая команда откажет в перезаписи. Для намеренного обновления добавить `--overwrite`. Вход, результат и отчёт должны иметь разные пути; исходник не перезаписывается.

В проверенном окружении системный псевдоним python не работал; использован уже установленный Python 3.14.5:

```powershell
& 'C:/msys64/ucrt64/bin/python.exe' -B -m ai_ds.data --input data/fixtures/pois.synthetic.json --output data/processed/pois.synthetic.validated.json --report reports/data/poi-quality.synthetic.json --overwrite
& 'C:/msys64/ucrt64/bin/python.exe' -B -m unittest discover -s tests -v
```

Коды завершения CLI: 0 — без отклонённых записей; 1 — набор обработан, есть отклонения; 2 — ошибка чтения/формата/записи или недопустимое смешивание источников. Сводка идёт в stdout, ошибки запуска — в stderr. При ошибке записи возможно создание только части выходных файлов: запись пары результата и отчёта не является транзакцией.

## Данные и проверки

- `data/fixtures/pois.synthetic.json`: 16 вымышленных POI, восемь категорий минимум по два раза, многокатегорийные объекты, разные шкалы рейтинга, нулевая цена, допустимые null и недоступный объект.
- `tests/fixtures/pois.invalid.synthetic.json`: девять намеренно некорректных записей, включая две записи с одинаковым ID.
- Вход — массив POI. Пропущенные ключи не заполняются, строки не преобразуются в числа, категории не угадываются.
- Нормализация убирает крайние пробелы из ID, названия, города, ID источника и записи источника. Исходный объект не изменяется.
- Все записи с повторным нормализованным ID отклоняются. Совпадение источника/внешнего ID и названия после casefold/свёртки пробелов даёт предупреждение без объединения.
- Поиск похожих названий ограничен указанным точным сравнением нормализованных названий; нечёткий поиск и географические пороги не применяются.
- Смешивание источников или реальных и синтетических принятых записей запрещено в 0.1.
- null сохраняется. Отсутствие координат не запрещает структурно корректный POI, но его ID попадает в `routing_without_coordinates`.
- `availability: unavailable` не является ошибкой структуры. Recommendation должен обработать доступность по контракту.

Отчёт хранит `checked_at`, входной путь, источник, тип набора, индексы записей (с нуля), ID, поля, коды и уровни проблем. `rejected_count` считает записи, `issue_count` — все замечания; `records_with_warnings` считает уникальные записи с предупреждениями. Записи с информационной отметкой синтетики не входят в `records_without_issues`.

## Фактические проверки

После исправления кириллицы выполнены 18 unittest-тестов Data: все прошли. CLI на демонстрационном наборе: 16 входных, 16 принятых, 0 отклонённых, 16 записей с предупреждениями, 55 замечаний суммарно. На негативном fixture тестами подтверждены 9 отклонённых записей и код CLI 1.

Проверены типы и диапазоны, пропуски, шкалы, provenance, некорректный URL, boolean вместо числа, нечисловые JSON-константы, дубли, пустой вход, повреждённый JSON, повторяемость обработки и защита файлов. Временная метка CLI меняется между запусками; остальные диагностические результаты на одинаковом входе воспроизводимы.

## Исправление кириллицы в синтетических fixtures

При независимой проверке обнаружено, что при первоначальной генерации названия и город были заменены ASCII-символами `?`. Файлы при этом корректно декодировались как UTF-8: это была потеря текста до записи, а не ошибка JSON или последующего чтения.

По согласованию восстановлены только синтетические подписи: `Тестовый объект 01` … `Тестовый объект 16` и `Тестовый город`. В негативном fixture существующие названия восстановлены как `Тестовый объект 01`, а намеренно отсутствующее поле name оставлено отсутствующим. ID, числовые значения, категории, null и намеренные ошибки не менялись. Обработанный набор и отчёт пересозданы штатным CLI.

Добавлены две регрессии: точные русские строки в исходных/обработанном fixtures и сохранение кириллицы при полном CLI-проходе. Профили Recommendation обновляются владельцем этого компонента согласованно с восстановленным городом; Data не подменяет город ради обхода фильтрации.

## Передача Recommendation Agent

```python
from ai_ds.data import load_pois, process_pois

pois = load_pois('data/processed/pois.synthetic.validated.json')
accepted, report = process_pois(pois)
```

Результат — обычный массив POI по контракту, без добавленных диагностических полей. Отчёт: `reports/data/poi-quality.synthetic.json`. При загрузке нового входа проверять `rejected_count` до формирования запроса рекомендаций. Обязательные ID профиля, город запроса и пригодность признаков конкретной модели проверяются на последующем этапе; этот модуль профиль не принимает.

Данные содержат null: рейтинг, популярность, стоимость, координаты, длительность. Не подставлять нули. Рейтинг в разных шкалах требует обработки утверждённой моделью. Все POI синтетические; показатели не являются реальными наблюдениями.

Не проверены: соответствие координат реальному городу, фактическая достоверность и свежесть, часы работы, реальная маршрутизация, бюджет поездки и пользовательская полезность. Реальные источники и загрузчик ещё не реализованы. Контракт, ранжирование, маршрутизатор, чужие модули и статусы TASKS.md не изменены.
