# Однодневный baseline day-enumeration-v0.1

Реализация по отдельно согласованному [дополнению Routing](routing-contract-v0.1.md). Исходный contracts-v0.1.md, POI, модель Recommendation и чужие модули не меняются. При работе применены проверки скилла route-validation: обязательные места, время, отдых, направленные переходы, неизвестные данные и честные статусы.

## Алгоритм

Кандидаты — top-K Recommendation плюс обязательные ID, всего не более восьми. Перебираются все непустые подмножества и их перестановки (до 109600 непустых последовательностей при восьми кандидатах). Рассматриваются только последовательности со всеми обязательными ID.

По известным длительностям, направленным переходам и явным перерывам проверяются дневное окно и активный лимит. Unreachable блокирует последовательность. Missing/unknown или неизвестная длительность не заполняются: сумма известной части служит только нижней границей для доказуемого отсечения. Последовательность с неопределённостью не превращается в рассчитанное расписание.

Среди рассчитанных последовательностей выбирается:

1. Максимальный лексикографический вектор включения по Recommendation.rank.
2. При равенстве — минимальная сумма секунд перемещений.
3. При равенстве — лексикографический порядок ID.

Численные веса полезности не вводятся. Обязательные ID вне top-K не получают вымышленный rank. Перебор точен для ограниченной задачи по предоставленным известным данным, но не обещает глобально оптимальную туристическую поездку при неполной матрице, ограниченном top-K и непроверенных фактах.

Темп не сводится к числу объектов: явно задаются активный лимит и отдых. Но коэффициенты для трёх темпов не выведены и F06 не закрыта. Бюджет, часы, обед, гостиница и реальная навигация не проверяются. Многодневный профиль отклоняется.

## Файлы и запуск

- ai_ds/routing.py — build_route и локальный CLI.
- examples/routing/day.synthetic.json — направленная синтетическая матрица и явный контекст.
- tests/test_routing.py — контрольные расписания, ошибки и регрессии.

```powershell
python -B -m ai_ds.routing --pois data/processed/pois.synthetic.validated.json --preferences examples/preferences/history.json --scenario examples/routing/day.synthetic.json
python -B -m unittest discover -s tests -v
```

В текущем окружении проверяется уже установленным Python 3.14.5:

```powershell
& 'C:/msys64/ucrt64/bin/python.exe' -B -m ai_ds.routing --pois data/processed/pois.synthetic.validated.json --preferences examples/preferences/history.json --scenario examples/routing/day.synthetic.json
& 'C:/msys64/ucrt64/bin/python.exe' -B -m unittest discover -s tests -v
```

Новые зависимости не нужны. Требуется доступная база часовых поясов, как в Recommendation. CLI вычисляет рекомендацию публичной функцией recommend и передаёт в Routing; результат печатается в UTF-8 JSON, файлы не перезаписываются.

## Демонстрационный результат

На исходном history-профиле и приложенном сценарии: museums-01 09:00–09:30; отдых до 09:45; переход 600 секунд; museums-09 09:55–10:25; отдых до 10:40; переход 600 секунд; history-02 10:50–11:35. Все ID имеют префикс synthetic:.

Активное время: 6300 секунд посещений + 1200 переходов = 7500 секунд, не более 9000. Отдых 1800 секунд; общее время 9300 секунд, помещается в 09:00–12:00. Два перехода, у второго неизвестное расстояние. Некоторые другие пары отсутствуют, поэтому UNRESOLVED_CANDIDATE_DATA сохраняется. Общий status = unknown, time = passed, budget = not_checked, opening_hours = unknown.

Обязательный POI вне top-K отдельно проверяется тестом: museums-01 09:00–09:30, отдых 900 секунд, переход 600 секунд, history-02 09:55–10:40. Неизвестные часы не означают открытость.

## Приёмка и ограничения

Первичная проверка исполнителя: 54 unittest-теста прошли. Независимый QA затем обнаружил округление огромных целых секунд в Decimal context и недостаточную проверку categories в объяснениях снимка. Исправлены: int умножается точно, float преобразуется через Fraction(str(value)) без округления; MATCH-объяснения требуют реального полного пересечения категорий. Добавлены две регрессии. Итоговый повторный прогон исполнителя на Python 3.14.5: 56/56 тестов прошли (18 Data, 18 Recommendation, 20 Routing). Реальный Routing CLI ранее завершился кодом 0 с расписанием 09:00–11:35; его subprocess-проверка также входит в итоговый прогон. Независимый целевой ретест исправлений выполняется отдельно QA.

Проверяются точное попадание в границу и переполнение на секунду, активный лимит, отдых, нулевой отдых, дробные секунды, огромные int без float-overflow, обязательный вне top-K, направленность и unreachable, missing/unknown, неизвестная длительность, null distance, бюджет другой валюты без конвертации, пустой набор, предел восьми кандидатов, неверный/многодневный контекст, даты/смещения, транспорт, дубли пар, неверные типы, снимок Recommendation, повторяемость и неизменность входа. Реальные subprocess-байты CLI проверяются при cp1251.

Реальные POI, точность тестовых переходов, пользовательская полезность, веб-интеграция, сохранение, Route Assistant и полноценная навигация не проверены. TASKS.md не изменён.
