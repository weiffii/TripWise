1. Сначала читать `PROJECT_OVERVIEW.md`, `FEATURES.md`, `ROADMAP.md`, текущий `TASKS.md` и реальный репозиторий.
2. Не ставить `[x]` без проверяемого результата; старые дедлайны не превращать в «выполнено».
3. Для новой функции проверять её место в P0/P1/P2; после 22 ноября не расширять MVP при нестабильном ядре.
4. Не изменять согласованные требования, модель, архитектуру и сроки без разрешения.
