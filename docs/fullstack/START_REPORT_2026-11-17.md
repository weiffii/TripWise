## Как читать структуру

В main:

- AGENTS.md — правила работы агента с проектом. Вводное «я» относится к AI/DS-направлению автора; текущая пользовательница отвечает за Fullstack.
- .agents/skills/ — повторяемые инструкции для анализа и проверок; сам файл не доказывает применение.
- .codex/ — конфигурации ролей; наличие файла не доказывает запуск отдельного агента.
- docs/ — требования, роли, планы и задачи.
- docs/fullstack/ — результаты текущего этапа Участника 2.

Дополнительно только в feature/ai-ds:

- ai_ds/data.py — загрузка JSON, проверка и нормализация сведений о местах.
- ai_ds/recommendation.py — персонализированное ранжирование; recommend принимает профиль и места.
- ai_ds/routing.py — build_route строит однодневное расписание по рекомендации и переданной матрице переходов.
- ai_ds/demo.py — запуск рекомендаций из терминала.
- ai_ds/sources/overpass.py и ai_ds/normalize_pois.py — получение и преобразование OSM.
- data/, examples/, tests/ — наборы, примеры входов и автоматические проверки.
- docs/ai/contracts-v0.1.md и routing-contract-v0.1.md — форматы обмена данными. Второй документ уточняет сигнатуру build_route и имеет значение при интеграции.

POI означает место интереса, например музей. JSON — текстовый формат передачи данных. Контракт — договорённость о названиях, типах и смысле полей, общая для интерфейса, сервера и модуля AI/DS.

## Выполненные проверки

Чтобы не переключать рабочую ветку на код напарника, снимок origin/feature/ai-ds был извлечён во временную папку. Все команды ниже запускались именно из неё. В текущей feature/fullstack модулей ai_ds и tests пока нет.

```sh
python3 -B -m unittest discover -s tests -v
python3 -B -m ai_ds.demo --pois data/processed/pois.synthetic.validated.json --preferences examples/preferences/history.json
python3 -B -m ai_ds.demo --pois data/processed/pois.synthetic.validated.json --preferences examples/preferences/nature.json
python3 -B -m ai_ds.routing --pois data/processed/pois.synthetic.validated.json --preferences examples/preferences/history.json --scenario examples/routing/day.synthetic.json
```

Результат: 74 теста, OK, код завершения 0: 18 Data, 18 Source/Normalization, 18 Recommendation, 20 Routing. Исторический профиль дал первые ID museums-01, museums-09, history-02; природный — unusual-08, nature-03, nature-11 (все с префиксом synthetic:). Различие результатов подтверждено на контролируемом наборе, полезность для реальных туристов не проверена.

Routing CLI завершился кодом 0: посещения 09:00–09:30, 09:55–10:25, 10:50–11:35. Общий status = unknown; time = passed; budget = not_checked; opening_hours = unknown; required_places = passed. Два тестовых перехода по 600 секунд; у второго distance_meters = null. Линии и внешних ссылок нет. Успешный запуск не означает полную выполнимость туристической поездки.

Сетевая загрузка реальных POI, браузерный сценарий, HTTP, БД, сторонний MCP и отдельные субагенты этой проверкой не подтверждены. Существующая ошибка приложения не исправлялась; этот пункт защиты предстоит выполнить на реальном воспроизводимом случае.

## Риски интеграции

1. AI/DS ещё не объединён с main. Отсутствие ai_ds в твоей ветке сейчас ожидаемо. Нельзя копировать его вручную поверх будущих обновлений: предпочтителен проверенный PR напарника в main, затем получение общей версии.
2. Однодневный baseline отклоняет многодневный запрос и ограничен восемью кандидатами. Нельзя просто показывать форму на неделю и считать многодневность готовой.
3. Routing ждёт полный набор мест, Recommendation, travel_times и routing_context. Нужны согласованные часы дня, отдых и активный лимит. Не подставлять произвольные значения как утверждённые правила темпа.
4. Карта с маркерами не заменяет Routing API. Прямые отрезки и тестовые 600 секунд нельзя подписывать как дорожный пеший маршрут.
5. Нельзя преобразовывать неизвестное null в нулевую стоимость, нулевое расстояние или открытость места.
6. Форматы ошибок и предупреждений различаются между Recommendation и TripRoute; сервер должен явно преобразовывать их для интерфейса.

## Предложение по технологиям

Python + FastAPI на сервере совместимы с уже существующим Python AI/DS. SQLite подходит для локального учебного сохранения. Обычные HTML/CSS/JavaScript позволяют начать без отдельной сборки интерфейса. Leaflet/OSM соответствуют исходному плану. Это предложения к согласованию перед первым кодом; пакеты и внешние сервисы не подключались. Конкретный пеший провайдер выбирается после проверки поддержки walking, доступа и условий использования.
