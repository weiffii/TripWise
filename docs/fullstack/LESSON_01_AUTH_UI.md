# Первый экран входа и регистрации

Дата: 17 ноября 2026 года. Ветка разработки: feature/fullstack.

## Что сделано

Созданы frontend/index.html, frontend/styles.css и frontend/auth.js. Это frontend-прототип входа и регистрации, соответствующий согласованному входу по почте и паролю. Сервер, пользователи, сессии и хранилище ещё не реализованы. После корректного заполнения показывается пояснение о прототипе, а не ложное сообщение об успешном входе. Переход к защищённым страницам не имитируется.

Поля регистрации: почта, пароль и повтор пароля. Вход: почта и пароль. Минимум восемь символов при регистрации — временное правило для упражнения с валидацией, а не согласованная окончательная политика паролей. Данные не отправляются, не сохраняются в localStorage и не пишутся в журнал. Для проверки использовать только вымышленные данные.

HTML — структура: заголовки, поля, кнопки. CSS — внешний вид, расстояния и расположение. JavaScript — поведение: переключение режима, показ пароля, сравнение паролей, сообщение после проверки.

## Как посмотреть

Можно открыть frontend/index.html двойным щелчком через Finder: внешних библиотек и установки пакетов нет. Стили и скрипт находятся рядом с HTML и подключаются относительными путями.

Для просмотра по локальному HTTP из корня проекта:

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory frontend
```

python3 запускает Python. -m выбирает готовый модуль http.server. 8765 — порт, то есть номер локального адреса приложения. --bind 127.0.0.1 ограничивает доступ этим компьютером. --directory frontend указывает папку отдаваемых файлов. Открыть http://127.0.0.1:8765. Остановить сервер сочетанием Control+C в том терминале, где он запущен. Это сервер выдачи статических файлов, а не backend регистрации.

При агентной проверке порт 8000 оказался занят; использован 8765. Чужой процесс не останавливался.

## Что проверено

Проверка выполнена вручную через настоящий браузер на локальной странице:

- Включение регистрации показывает повтор пароля и меняет подписи; возврат ко входу скрывает и отключает дополнительное поле.
- Два разных тестовых пароля блокируют отправку и дают сообщение «Пароли не совпадают».
- Одинаковые тестовые пароли и корректная почта дают сообщение о проверке интерфейса, без создания аккаунта.
- После проверки поля паролей очищаются.
- Почта без @ блокируется стандартной проверкой браузера.
- Кнопка показа пароля переключает поле в текстовый режим и меняет подпись на «Скрыть».
- Корректно заполненный вход сообщает, что сервер не подключён и вход не выполнен.
- Экран визуально проверен в доступной узкой области браузера. Обнаружено слипание слов заголовка на узком экране; исправлены правила переноса в CSS, результат повторно просмотрен. Это дефект оформления прототипа; не следует выдавать его за исправленную ошибку готового пользовательского сценария.

Компьютерный широкий экран отдельно не проверен в браузере. Есть CSS-раскладка для широкого экрана; её наличие само по себе не является визуальной проверкой. Автоматические тесты этого прототипа не создавались. Тесты AI/DS в этом шаге не запускались и его файлы не менялись. Публикация, коммит и push не выполнялись.

## Упражнение

Открыть страницу, выбрать «Регистрация», указать student@example.com и два разных вымышленных пароля длиной от восьми символов. Нажать «Создать аккаунт», прочитать ошибку. Исправить повтор пароля и повторить проверку. Аккаунт при этом не появится: соответствующего сервера ещё нет.
