# Пробные задачи агентов Участника 2

Дата: 17 ноября 2026 года. Координатор — основной чат. Этот документ фиксирует полученные результаты отдельных исполнителей, а не заменяет их запуск.

После завершения 08_FULLSTACK_AGENT_IMPLEMENTATION.md координатор фактически запустил две отдельные задачи /root/frontend_agent и /root/backend_agent. Каждая получила явное требование сначала прочитать свой новый TOML и выполнить ограниченную задачу без изменений приложения. Параллельно отдельный qa_agent проверял файлы настройки относительно исходного снимка.

## Проба frontend_agent

Исполнитель сообщил о фактическом чтении .codex/agents/frontend_agent.toml, AGENTS.md, frontend/questionnaire.js, backend/pages/questionnaire.html и frontend/styles.css, а также о просмотре требований и текущей ветки feature/fullstack.

Верно определил область: назначенные HTML/CSS/JavaScript и UI-шаблоны backend/pages/, без самостоятельного изменения Python, API или AI/DS. Объяснил путь HTML → сбор JSON → PUT → сообщение о сохранении только после подтверждения. Отдельно указал необходимость сохранять исходные owner_context и revision, не переносить анкету после смены аккаунта и не стирать локальные поля при ошибке.

Подготовил учебный пример: найти --primary в frontend/styles.css; различить структуру HTML, оформление CSS и поведение JavaScript. Проект, браузер, сервер и данные не изменял; тесты не запускал.

## Проба backend_agent

Исполнитель сообщил о фактическом чтении .codex/agents/backend_agent.toml, AGENTS.md, backend/main.py, backend/drafts.py, backend/accounts.py, docs/PROJECT_OVERVIEW.md и docs/FEATURES.md.

Верно определил область: FastAPI, HTTP, серверная проверка, SQLite, аккаунты, сохранение и согласованные адаптеры. Отделил её от UI и алгоритмов напарника. Объяснил current_user, возврат контекста при GET, сравнение контекста и revision внутри записи, выбор владельца только по сеансу. Назвал временную TRIPWISE_DB_PATH, вымышленных пользователей и собственный порт как безопасную тестовую среду, не настоящую базу участницы.

Подготовил простое объяснение: сервер сначала проверяет вошедшего пользователя, принадлежность открытой формы и версию, затем записывает данные. Код и данные не менял, сервер и тесты не запускал.

## Границы подтверждения

Это реальные отдельные исполнения по явно прочитанным новым инструкциям. Название задачи не выдаётся за автоматическую загрузку файла TOML. Автоматическое обнаружение новых конфигураций уже открытым сеансом отдельно не проверено. В текущем чате координатор может явно передавать соответствующий путь инструкции при делегировании.

Пробы не подтверждают готовность карты/генерации, независимую приёмку продукта, авторство собственного Fullstack-скилла или сторонний MCP. Проверка самих файлов настройки находится в отдельном 09_FULLSTACK_AGENT_QA.md. Коммит и push настройки не выполнялись.
