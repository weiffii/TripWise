Москва принимает только RUB; Шанхай — RUB/USD/EUR/CNY с существующими фиксированными учебными коэффициентами, не живыми курсами. Поддерживаются восемь категорий и набор режимов транспорта.
- Обязательные точки должны использовать реальные ID из `/api/planned-trips/catalog/{moscow|shanghai}`, а не ID небольшого каталога интерфейса.

## Выбор решения

Рассмотрены хранение всех генераций в БД с флагом видимости и хранение плана только у клиента. Первое не соответствует требованию не сохранять до кнопки; второе позволяет прислать серверу изменённый клиентом план и требует отдельной проверки содержимого.

Координатор принял временный серверный preview: ограниченный по размеру кэш в памяти, TTL 60 минут, случайный идентификатор, привязка к пользователю и хешу текущего cookie-сеанса. До явного сохранения в `planned_trips` нет INSERT/UPDATE. Перезапуск сервера теряет несохранённый preview — интерфейс должен объяснять это обычным сообщением о необходимости построить заново.

## Контракт нового сценария

1. `POST /api/route-previews` принимает `{form_preferences: <fullstack 0.2>, source_preview_id?: <id>}`. Сервер выполняет адаптацию к существующему движку; клиент не присылает одновременно разные копии engine/preferences. Ошибки несовместимых полей не скрываются усечением.
2. Генерация возвращает объект существующей формы маршрута с `route_id`, `version`, `city`, `preferences` движка, `form_preferences` анкеты, `options`, `plan`, `poi_snapshot_id`; дополнительно — `preview_id`, `is_preview: true`, `owner_context`.
3. `GET /api/route-previews/{id}` возвращает этот объект только владельцу текущего сеанса. Истёкший/чужой preview не раскрывает данные другого пользователя.
4. `POST /api/route-previews/{id}/save` принимает `{version}` и требует свой Origin и `X-TripWise-Draft-Owner`. Сохраняется доверенный план из серверного кэша, а не произвольный `plan` из тела запроса. Повтор успешного сохранения того же preview не создаёт дубликат.
5. `POST /api/planned-trips/{route_id}/preview` принимает `{version}` и создаёт временную копию сохранённого маршрута. Кэш удерживает `source_route_id` и `source_version`; повторная генерация по `source_preview_id` наследует их. Явное сохранение обновляет исходную запись только при совпадении версии, иначе 409 без перезаписи.
6. `DELETE /api/planned-trips/{route_id}` принимает `{version}`, требует Origin и owner-context. Чужая запись не удаляется; изменённая версия вызывает конфликт. UI запрашивает подтверждение до запроса.
7. Старые маршруты, каталог и `/api/trips` сохраняют совместимость. GET списка рассчитанных маршрутов добавляет `owner_context`. Список UI объединяет два типа, сохраняя разные id/API и подписи «Анкета» / «Маршрут».

## Редактирование и интерфейс

Результат preview открывается по `/trip/result?preview=id`, сохранённый — по `?route=id`. «Редактировать» сохранённый маршрут сначала создаёт preview. Редактирование анкеты preview использует `/trip/new?preview=id`; после генерации передаётся `source_preview_id`.

Чат использует существующие сервисы ассистента. Если в качестве рабочего маршрута выбран preview, подтверждение предложения меняет только кэш; постоянная запись меняется лишь кнопкой «Сохранить поездку». Профильный backend может сохранить совместимые alias существующих assistant-путей, но обязан применять проверку сеанса preview и не выполнять старый SQL UPDATE для него. Путь обязан быть согласован с frontend и проверен тестом.

Дата/время берутся по часовому поясу города. Адаптер использует начало первой прогулки и окончание последней; полные промежуточные дни требуют видимых пользователю часов по умолчанию либо явных полей. Запрещено молча изменять выбранные даты, бюджет, интересы и обязательные точки. Старое `car → taxi` движка должно иметь соответствующую подпись, а не обещание расчёта собственного автомобиля.

## Проверки и ограничения

Нужны тесты: генерация без записи в БД; preview другого пользователя/сеанса; TTL; повторное Save без дубликата; preview-edit без изменения оригинала; Save с конфликтом версии; независимые Москва/Шанхай; сохранность старых анкет и маршрутов; каталог реальных ID; активные и разрабатываемые направления; ошибки движка; отсутствие ключа LLM и недоступность Node без ложного успеха. Интеграционный запуск должен использовать временную БД, локальный движок и не включать платные LLM/API.

Рассчитанная линия и оценки времени/цен не становятся проверенной реальной навигацией от одного объединения веток. Происхождение и учебные/приблизительные поля сохраняются. Публичное размещение, новые провайдеры и изменение математической модели не входят в этот срез. Статусы `TASKS.md` без подтверждения не меняются.
