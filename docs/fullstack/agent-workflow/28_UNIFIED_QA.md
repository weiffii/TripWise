# Независимая проверка объединённого TripWise

Дата: 22 ноября 2026. Исполнитель: отдельный QA Agent. Ветка проверки — `feature/fullstack-unified`, объединение исходных `integration/fullstack-ai-ds` и `feature/fullstack`. QA прочитал AGENTS.md, скилл `qa-integration-check`, проект решения24, требования25 и правила источников данных. Математические модели и рабочая база участницы этим агентом не изменялись.

## Фактически выполненные проверки

1. **67/67 HTTP-тестов прошли** за38.696с с `-W error::ResourceWarning`, `NO_PROXY=127.0.0.1,localhost`, выключенным `OPENROUTER_API_KEY` и локальным Node в PATH. Запущены все `test_*.py` из `tests/fullstack`, **кроме** `test_shanghai_integration.py`: его TestClient требует отсутствующий `httpx2` для установленной версии Starlette. Новые зависимости не устанавливались. Пропущенный модуль не считается пройденным.
2. Отдельно прошли стандартные алгоритмические наборы: `test_routing_v02_contract.py` —18 тестов; `test_multiday.py` —25; `test_recommendation.py` —20. Последние20 повторены после исправления совместимости версии профиля рекомендаций. Эти результаты не являются оценкой актуальности цен или живой пешеходной навигации.
3. **Реальный headless Chrome / Playwright: PASS**, сценарий `tests/fullstack/browser_unified.cjs`. Использовались отдельный сервер, временная SQLite и вымышленный аккаунт. Внешние запросы браузера заблокированы; API-ключ LLM удалён из окружения тестового сервера. Профиль пользовательского браузера не использовался.

HTTP-набор покрывает прежние аккаунты/анкеты/CRUD, owner-context, Origin, revision, миграцию, а также новый контракт preview. Контрактный `test_route_preview.py` подставляет генератор; это прямо указано в файле. Работу настоящего движка для обоих городов проверяет отдельный браузерный сценарий ниже.

## Реальный сквозной сценарий

- Главная → модальная регистрация → новая анкета. В странах первыми RU/CN; остальные варианты недоступны для выбора.
- Москва, один день09:00–19:00, RUB6000, три основных интереса: история, музеи, природа. Движок действительно вернул посещения; расписание и SVG-карта отрисовались без JavaScript-ошибок.
- До «Сохранить поездку» проверено непосредственно в временнойSQLite: `saved_trips=0`, `planned_trips=0`.
- Явное Save создало одну запись. Повтор Save того же preview с той же версией вернул тот же route_id, количество записей не изменилось.
- Создан отдельный Шанхай, один день09:00–19:00, CNY1000, те же три интереса. Настоящий движок вернул посещения; до Save оставалась только ранее сохранённая Москва. После Save — две независимые карточки.
- Edit Москвы создал временную копию; изменение бюджета на7000 и повторная генерация **не меняли** прежний сохранённый JSON. Только Save обновил прежний route_id и увеличил version на1; количество поездок осталось2.
- Отмена удаления Шанхая сохранила обе записи; подтверждение удалило только выбранную запись. Оставшаяся Москва сохранилась.
- Логотип вернул на главную. На375px `scrollWidth=375`; переключатель действительно изменил тему. За весь сценарий pageerror отсутствовал.

Артефакты находятся в `/tmp/tripwise-unified-browser/`: `moscow-preview.png`, `shanghai-preview.png`, `two-saved-routes.png`, `mobile-home.png`, `result.json`. Скриншоты Москвы и мобильной главной дополнительно просмотрены QA. Подложка внешней карты намеренно не загружалась: видимая геометрия и отметки на ней не выдаются за проверенный реальный путь.

Команда повторения браузерной проверки в текущей macOS-среде:

```sh
env -u OPENROUTER_API_KEY PATH="/Applications/ChatGPT.app/Contents/Resources/cua_node/bin:$PATH" /Applications/ChatGPT.app/Contents/Resources/cua_node/bin/node tests/fullstack/browser_unified.cjs
```

Для другой среды скрипт принимает `TRIPWISE_PLAYWRIGHT` и `TRIPWISE_CHROME`; Node, установленный Chrome/Chromium и уже имеющийся Playwright должны быть доступны. Это не добавление зависимости в приложение.

## Обнаруженные и исправленные проблемы

- QA заметил по коду, что общий helper результата добавлял `request_id` в Save/fork. Сервер принимает там только `{version}` и отклоняет лишние поля. Проблема передана frontend-агенту; он ограничил request_id путями assistant. Последующий реальный UI Save/fork прошёл. До исправления этот отказ исполнением QA не воспроизводился — исходное обнаружение было статическим.
- Координатор выявил несовместимость настоящей Москвы с тремя интересами в старом профиле рекомендаций. Он согласовал профиль0.2, сохранив старый контракт0.1; реальная генерация трёх интересов и20 тестов рекомендаций после изменения прошли. QA не менял формулу ранжирования.
- В самом новом тесте исправлены два ожидания: допустим `?new=1` после регистрации; ожидание анкеты теперь сначала ждёт навигацию и наличие fieldset, затем enabled. Эти исправления тестового кода не меняли ожидаемое поведение продукта.

## Ограничения и оставшиеся риски

- Старый TestClient-модуль не запускался из-за отсутствующего httpx2. Живые платные LLM/API и внешние tiles/дорожные сервисы не вызывались. Шанхай без LLM-ключа может честно показать недоступность помощника; редактирование параметров и повторная генерация проверены.
- Подтверждение AI-предложения без постоянной записи проверено контрактным тестом с контролируемым сервисом. Неподменённое LLM-редактирование не заявляется.
- Реальный браузер проверил ходовые режимы по умолчанию и один день. Полный перебор многодневных/смешанных транспортных сценариев не является частью этого сквозного прогона; часть ограничений проверяется HTTP/алгоритмическими тестами.
- Координатор отдельно проверил9 старых тестов Moscow V7:6 прошли,2 завершились неуспехом и1 ошибкой. По его повтору на архивном HEAD те же три результата существовали **до объединения**. QA самостоятельно этот baseline не запускал; его нельзя записывать как9 успешных тестов интеграции.
- Предпросмотры хранятся в памяти сеанса с TTL и теряются при перезапуске. Сохранённые поездки находятся в SQLite. Актуальность цен/часов и достоверность оценочных слоёв данными тестами не устанавливается.
