# Объединённый интерфейс TripWise

Дата: 22 ноября 2026. Ветка: `feature/fullstack-unified`.

## Задание и принятые решения

По подтверждённому пользовательскому сценарию анкета создаёт временный маршрут, после просмотра доступны редактирование и отдельное сохранение поездки. Доступные направления — Россия/Москва и Китай/Шанхай; остальные показаны с пометкой «В разработке» и отключены.

Конфликты в `backend/pages/questionnaire.html`, `backend/pages/trips.html`, `frontend/questionnaire.js`, `frontend/trips.js`, `frontend/styles.css` разрешены вручную: интерфейс из `feature/fullstack` соединён со всеми стилями карты, расписания и помощника интеграционной ветки. Корневые Git-операции, Python и AI/DS не менялись этим исполнителем. Индекс Git не отмечался разрешённым — это делает координатор после проверки.

## Изменения

- Сохранены главная, модальная авторизация, обе темы и иллюстрированная анкета. Текст главной отражает создание маршрутов Москвы и Шанхая. Добавлена авторская SVG-иллюстрация Шанхая, явно обозначенная как иллюстрация в ресурсах.
- Анкета отправляет один снимок параметров в `POST /api/route-previews`; ввод и загрузка формы не сохраняют поездку. Редактирование параметров предварительного маршрута загружается через `?preview=...`; повторная генерация передаёт `source_preview_id`.
- Список обязательных мест берётся из фактического каталога движка. Одновременно отображаются первые 60 совпадений; выбранные места остаются отдельными удаляемыми метками. Это сохраняет несколько обязательных мест и не создаёт десятки тысяч элементов DOM.
- В результате сохранены прежние функции расписания, карты, отображения неопределённости и предложений помощника. Добавлены «Редактировать», «Сохранить поездку» и «Изменить анкету». Изменение сохранённой поездки сначала создаёт временную копию. Помощник сохранённой записи не изменяет её напрямую через новый интерфейс.
- «Мои поездки» показывает сохранённые маршруты и отдельно прежние анкеты. Идентификаторы анкет и маршрутов не подменяются. У маршрутов есть открытие, редактирование временной копии и удаление с подтверждением; запись удаляется из интерфейса только после успешного ответа.
- Требования owner-context, версии и сеанса сохранены. Значения из API помещаются в текстовые узлы; идентификаторы URL кодируются.
- Для маршрута видимы ограничения движка: 1–5 дней, до 30 человек в возрастной группе, дневное окно не меньше часа; промежуточные дни 09:00–21:00. Москва — RUB; Шанхай — RUB/USD/EUR/CNY. Недоступная валюта не заменяется молча другой и не меняет смысл суммы: форма просит явно выбрать доступную валюту и указать бюджет в ней.
- Версии CSS/JS обновлены во всех четырёх HTML для получения объединённых ресурсов без старого браузерного кэша.

## Найденная проблема и исправление

Общий помощник HTTP из прежнего `trip-result.js` добавлял `request_id` ко всем POST. Это несовместимо со строгим телом `{version}` для сохранения/создания временной копии. QA также выявил проблему при чтении. Исправлено: `request_id` добавляется только к путям `/assistant/`. До исправления выполнение этого сценария данным исполнителем не проверялось; независимая регрессия передана QA.

## Выполненные проверки

Пять JavaScript-файлов (`questionnaire.js`, `trips.js`, `trip-result.js`, `auth.js`, `destination-visuals.js`) успешно разобраны настоящим `node:vm.Script` через Node REPL. Финальный разбор повторён после правки проверки валюты — все пять файлов прошли. Независимая поведенческая проверка остаётся за QA. `git diff --check -- frontend backend/pages` прошёл на момент проверки. Общая проверка Git в тот момент показывала неразрешённый README вне ответственности исполнителя.

Браузерный инструмент CUA в текущем сеансе недоступен. Реальный маршрут, сохранение, карта и помощник не объявляются проверенными данным исполнителем: их проверяют координатор и отдельный QA. Заглушки не выдаются за внешние вызовы.

## Незавершённое согласование

Прежняя анкета определяет бюджет только для питания и развлечений; движок напарника учитывает также переходы. Координатор запросил решение пользователя. Математика движка и утверждённая подпись самостоятельно не изменялись; итоговое согласование должно отразиться в UI и тестах до приёмки.

## Объяснение для обучения

`questionnaire.js` готовит параметры, сервер создаёт временный маршрут, `trip-result.js` показывает расписание и карту. Только нажатие «Сохранить поездку» отправляет запрос записи в аккаунт. Редактирование использует временную копию, поэтому отклонённые правки не меняют сохранённую поездку.

Практика: создать маршрут Москвы, до сохранения открыть «Мои поездки» в другой вкладке, затем сохранить и проверить появление карточки. Вопрос: почему генерация и сохранение теперь два отдельных запроса?
