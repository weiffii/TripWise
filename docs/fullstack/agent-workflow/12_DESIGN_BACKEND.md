# Сервер: валюта бюджета и состав компании

Дата: 19 ноября 2026 года. Исполнитель: отдельный `backend_agent` задачи `design_backend`; перед реализацией прочитал собственную инструкцию `.codex/agents/backend_agent.toml`, `AGENTS.md`, `PROJECT_OVERVIEW.md`, `FEATURES.md` и актуальные Fullstack-решения. Ветка проверена: `feature/fullstack`.

## Задание и изменения

По переданному аналитиком контракту изменены только:

- `backend/drafts.py` — модель `TravelerCounts`, проверка суммы и четыре разрешённые валюты, нормализация старого JSON при чтении;
- `tests/fullstack/test_travel_party.py` — восемь реальных HTTP-проверок;
- этот отчёт.

`budget_currency`: `RUB`, `USD`, `EUR`, `CNY`. Исходная `budget_amount` остаётся `Decimal` с прежними ограничениями. Конвертации, курсов валют, детских скидок и возрастных границ нет. Поле `schema_version` сохраняет значение `fullstack-draft-0.1`: это совместимое расширение черновика Участника 2, не утверждённый контракт AI/DS.

`traveler_counts` содержит обязательные целые `adults`, `children`, `seniors` от 0 до 100. Булевы значения, строки, дроби, лишние ключи, отрицательные значения, неполный состав и `null` отклоняются. Сумма равна `travelers`, для которого сохраняется диапазон 1–100. Самостоятельное правило «обязательно должен быть взрослый» не вводилось.

Только отсутствующее поле старой анкеты нормализуется в `adults=travelers`, `children=0`, `seniors=0`. При PUT сервер сохраняет полный нормализованный JSON. При GET старой записи нормализация выполняется только в ответе: `preferences_json`, `revision` и `updated_at` в SQLite не меняются. Это обеспечивает загрузку старой анкеты без ложных конфликтов версий.

Защиты Origin, session-owner, исходного `owner_context`, revision и транзакции сохранены. Новых таблиц, зависимостей, внешних сервисов и платных вызовов нет. Пользовательский сервер, реальная база и код Участника 1 не изменялись.

## Фактические проверки исполнителя

1. Первый запуск HTTP-тестов в ограниченной среде: 0 тестов, `socket.bind` получил `PermissionError`. Это ограничение среды, не успешная проверка.
2. Повтор с разрешением локального тестового сервера:

```bash
NO_PROXY=127.0.0.1,localhost no_proxy=127.0.0.1,localhost .venv/bin/python -W error::ResourceWarning -m unittest discover -s tests/fullstack -p test_travel_party.py -v
```

Результат: **8 тестов прошли, 4.419 секунды**, предупреждений ResourceWarning нет. Использованы временная SQLite и собственный свободный порт из существующего `LiveServerTests`; по окончании процесс тестового сервера остановлен средствами fixture.

Проверены четыре валюты без изменения суммы, PUT старого клиента, GET старого JSON без записи в БД, невалидные группы и сохранность предыдущих значений, суммарный лимит 100, отсутствие неутверждённых возрастных ограничений, неизвестная валюта и сохранность после перезапуска тестового сервера.

3. `git diff --check` и `python -m py_compile` для двух изменённых Python-файлов прошли.
4. Дополнительно прямой вызов Pydantic-модели подтвердил legacy-нормализацию, четыре валюты и отклонение четырёх невалидных групп.

Это проверки разработчика, не независимая приёмка. Браузерные сценарии не выполнялись этим исполнителем.

## Передача QA и ограничения

Независимому QA следует запустить весь `tests/fullstack`, проверить новые поля в браузере и повторить регрессию смены аккаунта QA-01. В старом `test_drafts.py` две строгие проверки полного JSON сравнивают его с helper без состава компании: ожидаемое значение необходимо адресно дополнить `traveler_counts`; это следствие нового согласованного ответа. Этот исполнитель старые тесты по назначенным границам не изменял и уведомил координатора до передачи.

Генерация маршрута и учёт состава группы алгоритмами не подключены: эти сведения пока только валидируются и сохраняются. Курсы валют и переход от суммы в выбранной валюте к ценам POI требуют отдельного согласования с Участником 1.

Для обучения: браузер отправляет сумму, валюту и три количества, сервер повторно проверяет их, затем сохраняет JSON в строку черновика текущего пользователя. Практика после обновления сервера: выбрать EUR и состав 2 взрослых + 1 ребёнок, сохранить анкету, повторно открыть и проверить значения. Вопрос на понимание: почему смена валюты в таком интерфейсе не должна автоматически превращать 100 EUR в 100 RUB?
