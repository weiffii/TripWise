## Содержательная проверка инструкций

### Frontend

Есть ответственность за текущие HTML/CSS/JavaScript, страницы и формы, расписание/карту/переходы, состояния загрузки/ошибок, чат с подтверждением правок. Сохранены простой стек и сине-голубая палитра. HTML в backend/pages явно выделен как UI-область; Python backend не получает скрытого совместного владельца. Изменения интерфейсов передаются backend/architect.

Сохранена защита QA-01: первоначальные owner_context и revision, запрет подмены контекста после 401/смены аккаунта, различие ACCOUNT_CHANGED и обычного конфликта, отсутствие «сохранено» до ответа сервера. Клиентская валидация не подменяет серверную. Нельзя выдавать черновик за маршрут, null за ноль, прямую линию за реальную навигацию или синтетические данные за реальные. Реальная браузерная проверка и непроверенные размеры/сценарии разделены.

### Backend

Есть ответственность за Python/FastAPI, HTTP/API, SQLite, независимую серверную валидацию, аккаунты/сеансы, изоляцию, сохранение/загрузку и адаптеры согласованных AI/DS/Routing-интерфейсов. Владелец берётся из серверного сеанса, не клиентского user_id. Отдельно сохранены Origin, owner_context, revision, транзакции, параметризованный SQL, безопасное хранение паролей и регрессии QA-01.

Запрещено копировать алгоритмы/математические коэффициенты напарника, самостоятельно менять ai_ds/, его данные/тесты и общий контракт. Групповой бюджет, transport_modes, многодневность и вопрос отеля не становятся утверждёнными за счёт добавления полей. Ключи внешних API остаются на сервере; новые провайдеры, зависимости и платные вызовы требуют согласования.

### Общее

Обе инструкции содержат работу только по конкретному заданию после аналитика/проектировщика, разделение владельцев файлов и запрет одновременных правок. Есть проверка feature/fullstack и сохранение незакоммиченной работы; запрещены git init, reset --hard, force push и автоматический merge. Разделены файл, коммит и отправка на GitHub.

Обучение адаптировано к начинающей студентке на Mac: небольшие срезы, назначение файлов/функций, путь данных, одна практика и вопрос, объяснение команд. Общение объединяет координатор, чтобы не возникало параллельных потоков вопросов. Тесты используют временную базу и собственный порт, не останавливают сервер участницы и не читают реальные runtime/.env. Собственные проверки разработчика не называются независимой приёмкой; исправление передаётся QA на ретест. Файловая регистрация, обнаружение, вызов агента, применение скилла и сторонний MCP прямо разделены.

## Ограничения и передача

Снимок использован для проверки перечисленных конфигураций и адресных документов. QA не выполнял нового запуска Codex, не проверял автоматически доступный реестр типов субагентов, не менял ~/.codex и не получал доступ к глобальным секретам. Настройка не должна сообщаться как подтверждённое автоматическое обнаружение только по этому отчёту.

Координатору провести отдельные безопасные пробы frontend_agent и backend_agent с явным чтением своих инструкций и без записи кода/данных. Результат каждой пробы должен содержать фактически прочитанные файлы, ответственность и границы. Если автоматическое обнаружение не подтверждено, так и указать, не подменяя его именем задачи.

Отдельный собственный Fullstack-скилл, доказательство стороннего MCP, свежая интеграция AI/DS и готовность всего MVP остаются самостоятельными задачами. Коммит/push и обновление общих сроков/статусов этой приёмкой не выполнялись.
