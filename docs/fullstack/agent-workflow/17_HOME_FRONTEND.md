# Главная, ручное сохранение и расширенная анкета — Frontend Agent

## Задание и реализация

По новому запросу пользовательницы публичная главная объясняет назначение TripWise. Кнопки входа/регистрации открывают нативный dialog. «Создать поездку» проверяет сеанс и открывает регистрацию для гостя; успешный вход/регистрация из этого сценария ведёт прямо к анкете. Остальной вход ведёт к поездкам. Закрытие окна очищает пароли и возвращает фокус. Escape поддерживает нативный dialog.

Герой — три локальные фотографии разных городов с единым CSS-фильтром, плавной сменой и приближением. Это анимация фотографий, не видеозапись. Есть пауза и prefers-reduced-motion. Фотографии получены координатором, источники/авторы/лицензии доступны через footer и frontend/assets/README.md.

Анкета получает страны, города, часовые пояса, валюты и подборки обязательных мест через GET /api/catalog. UI использует schema fullstack-draft-0.2 с местным ISO-временем без offset и IANA-зоной выбранного города. Старый draft0.1 читается без автоматической перезаписи. Сумма и валюта сохраняются без конверсии. Первые четыре валюты выделены, остальные идут отдельной группой; названия локализованы Intl.DisplayNames с fallback.

Обязательных мест можно выбрать несколько, искать в подборке, удалять отдельными chips. При смене страны/города и наличии выбранных мест требуется подтверждение; отмена восстанавливает прежний select и сохраняет места. Пустая подборка/поиск имеют честное сообщение. Карточки темпа содержат авторские SVG-иллюстрации: спокойный, смешанный, активный; значения pace сохранены relaxed/balanced/intensive.

## Сохранение и защиты

Input/change/load не отправляют PUT. Только submit «Сохранить анкету» формирует один неизменяемый snapshot. Во время запроса повторный submit блокируется. Новые правки не отправляются автоматически: если editVersion изменился во время запроса, UI сообщает об оставшихся несохранённых данных и ждёт отдельного нажатия. beforeunload предупреждает о несохранённом. owner_context остаётся исходным, revision обновляется только после успеха, ACCOUNT_CHANGED/401/обычный конфликт версий различаются. В другой аккаунт локальные поля не переносятся.

«Мои поездки» использует город и валюту сохранённой анкеты. Анкета не называется готовым маршрутом. Главная и остальные страницы указывают текущую границу: генерация и карта ещё не подключены.

## Для обучения

CSS определяет оформление и движение фоновых фотографий, auth.js управляет окном аккаунта, questionnaire.js держит текущие поля в памяти вкладки и отправляет snapshot только после кнопки. Практика: заполнить анкету, уйти без сохранения и сравнить «Мои поездки» с результатом после кнопки. Вопрос: почему изменение поля больше не вызывает запрос PUT?

## Дополнение: соответствие фотографий направлению

`destination-visuals.js` выбирает только фиксированный локальный ресурс: Москва, Париж и Стамбул имеют соответствующие фотографии. Остальные направления и ещё не выбранный город получают нейтральную авторскую иллюстрацию `travel-landscape.svg`. Анкета (hero и summary), раздел поездок и сохранённая карточка используют одну CSS-переменную `--destination-image`. Название города не интерполируется в произвольный URL.
