# Публичная главная, ручное сохранение и расширение анкеты

Дата: 21 ноября 2026. Исполнитель: отдельный Analyst Agent. Применён `analyst-requirements`: прочитаны AGENTS.md, инструкция скилла, PROJECT_OVERVIEW/FEATURES/ROADMAP/TASKS и текущие main.py, drafts.py, index.html, auth.js, questionnaire.js. Это постановка нового среза по прямому изменению сценария пользователем; не отчёт о выполнении. Исходная ветка `feature/fullstack`, на момент чтения рабочее дерево было чистым.

## Что теперь утверждено пользователем

- Главная доступна публично и объясняет суть TripWise: планирование персонального путешествия по предпочтениям.
- «Создать поездку» для гостя открывает регистрацию в модальном окне; в шапке отдельно доступны вход и регистрация. После успешного входа/регистрации из этого сценария открывается анкета.
- Фоны с городами плавно меняются/анимируются, визуальный стиль остаётся согласованным. Светлая/тёмная темы сохраняются.
- Ограничение интерфейса только Москвой снимается; выбираются страна, затем город.
- Анкета выглядит современно, варианты темпа представлены карточками с изображениями.
- Валюты: RUB, USD, EUR, CNY первыми, затем остальные из поддержанного списка.
- Можно выбрать несколько обязательных достопримечательностей.
- Сохранение **только по явному нажатию кнопки**. Это заменяет прежнее пожелание автосохранения; скрытые PUT по input, таймеру, blur, смене темы, уходу или закрытию вкладки недопустимы.

Новые пользовательские пожелания относятся к интерфейсу и сохранению анкеты. Они не подтверждают готовность генерации, глобального POI-покрытия, карты, LLM или поддержки выбранных стран алгоритмом.

## Сценарии входа и сохранения

Главная не блокируется запросом `/api/auth/me`. Он может улучшить состояние шапки: вошедшему показываются «Мои поездки», гостю — вход/регистрация. По «Создать поездку» вошедший переходит на `/trip/new`; гость видит modal в режиме регистрации и после успеха идёт на `/trip/new`. Вход по кнопке шапки может вести к `/trips`. Точный следующий путь должен быть локально заданным разрешённым значением, не произвольным внешним redirect из URL. Auth API, проверка Origin, cookie и модель аккаунтов сохраняются.

Модальное окно: явная кнопка закрытия, Escape, фокус внутри и возврат фокуса к вызвавшей кнопке; скрытая форма не мешает главной. Не терять введённые поля при случайном переключении оформления. Движение фона не ухудшает читаемость; `prefers-reduced-motion` отключает анимацию. Изображения локальные, с подтверждённым источником/лицензией, без ложной подписи города.

Новая и открытая анкета меняются только в памяти страницы до «Сохранить». Кнопка явно сообщает действие, статус до нажатия — «Есть несохранённые изменения». Во время PUT сохранять **снимок на момент клика**; не запускать цикл, автоматически досылающий правки после клика. Практичный вариант — временно блокировать поля на время запроса. После успешного ответа обновить revision и показать сохранение. При ошибке поля сохраняются в странице, успех не показывается. До успеха серверная старая анкета остаётся прежней. При уходе с изменениями предупреждать о потере. Повторное открытие загружает последнюю явно сохранённую версию, а не несохранённую локальную правку.

## Совместимый Fullstack-контракт

Существующие `/api/trip-draft` GET/PUT, `revision`, `owner_context`, заголовок `X-TripWise-Draft-Owner`, 401/409/428 и владение через сеанс сохраняются. Версию `fullstack-draft-0.1` можно оставить для совместимого расширения списка допустимых значений; общий контракт AI/DS этим не меняется. Существующие черновики Москвы и четырёх валют должны читаться.

Рекомендуемый единый справочник — публичный `GET /api/travel-catalog`:

```json
{
  "countries": [
    {
      "code": "RU",
      "name": "Россия",
      "cities": [
        {
          "name": "Москва",
          "timezone": "Europe/Moscow",
          "pois": [
            {
              "id": "curated:moscow:kremlin",
              "name": "Московский Кремль",
              "source_url": "https://whc.unesco.org/en/list/545/"
            }
          ]
        }
      ]
    }
  ],
  "currencies": [{"code": "RUB", "name": "Российский рубль"}]
}
```

Это **предложенная структура**, не заявление о существующем эндпоинте или полном каталоге. Имена полей следует единообразно закрепить между исполнителями до интеграции. Пример curated-ID — локальный идентификатор TripWise, не OSM/Wikidata/AI/DS-ID. Карточка каталога подтверждает только источник имени места, не актуальные часы, стоимость, координаты или доступность. Полный AI/DS POI отдельно требует его обязательные поля и provenance.

В полном `preferences` остаются существующие поля; расширяются:

- `country_code`, `city`, `timezone`: строго связанная тройка из серверного справочника. Клиент не может сохранить произвольный city с чужим часовым поясом.
- `budget_currency`: код из того же списка, который показывает UI. Порядок RUB/USD/EUR/CNY, затем остальные по коду. Переводы валют можно локализовать через стандартный `Intl.DisplayNames`; названия должны иметь безопасный fallback к коду. Сумма по-прежнему Decimal-строка, без обменного курса/конверсии.
- `required_poi_ids`: несколько уникальных строк, только ID выбранного города из справочника; неизвестные, дублированные и принадлежащие другому городу отклонять без перезаписи предыдущих данных.

Состав взрослых/детей/пожилых, общая сумма1–100, интересы, темп, способы транспорта, бюджетная база и серверные проверки сохраняются. Нельзя автоматически скрыть или потерять старый сохранённый POI при изменении справочника: показать проблему, а не молча очистить при GET.

При смене города прежние обязательные места не должны отправляться как места нового города. Если выбор непустой, предупредить, что он относится к прежнему городу, и очистить только после явного изменения пользователем направления. Сервер независимо проверяет принадлежность.

## География, время и данные

Справочник первого среза — честно ограниченный, расширяемый, **не все города мира**. Быстрый вариант: Россия (Москва, Санкт-Петербург), Турция (Стамбул), ОАЭ (Дубай), Япония (Токио), Китай (Пекин), Таиланд (Бангкок), Грузия (Тбилиси). Это рекомендация стартового набора, не новое требование количества городов. Дополнительные города могут быть включены при корректной связи страны/зоны и проверенных источниках POI.

Hardcoded `isoMoscow(...)+03:00` и московские подписи/форматирование должны уйти. Нельзя брать часовой пояс компьютера пользователя или текущее смещение для иной будущей даты. Если включены города с переходом летнего времени, согласовать единый механизм local-date-time → ZoneInfo: несуществующее/неоднозначное местное время нужно явно обработать, не молча сдвинуть. Без этого безопаснее первый срез с зонами без сезонного перехода для пользовательских дат, но сервер всё равно проверяет правильное смещение относительно `timezone` в указанный момент. Старые aware-времена Москвы должны остаться валидными. Не превращать выбор страны в подтверждение расчёта международного маршрута.

В проверенном `.venv` **babel и pycountry отсутствуют** (`importlib.util.find_spec` вернул False). Новые зависимости ради справочников не нужны. Валюты брать из статического проверенного снимка ISO4217 с источником и датой получения; официальная страница [SIX — Data Standards](https://www.six-group.com/en/products-services/financial-information/market-reference-data/data-standards.html) доступна при аналитической проверке. Не выдумывать полный список из памяти; отличать денежные валюты от специальных/фондовых кодов и задокументировать политику отбора. Проверка списка при разработке не означает сетевой запрос при каждом открытии анкеты.

Реальные имена обязательных мест брать из страниц музеев/достопримечательностей или официального наследия. Проверены первичные страницы [UNESCO — Санкт-Петербург](https://whc.unesco.org/en/list/540/) (Эрмитаж, Зимний дворец, Адмиралтейство) и [UNESCO — Стамбул](https://whc.unesco.org/en/list/356/) (Святая София, ипподром, Сулеймание). Это достаточный источник для имени/местоположения города, но не для выдумывания цен, часов, точных координат или подробного путеводителя. Новые источники исполнители/координатор проверяют отдельно. Список должен быть расширяемым без переписывания проверок формы.

## Разделение задач и критерии

**Backend Agent:** `backend/main.py`, `backend/drafts.py`, новый Fullstack-справочник/ресурсы и собственные новые тесты. Реализовать единый каталог, проверку связанной географии/зоны/валют/мест, совместимость старых черновиков. Не менять accounts.py, чужие AI/DS и настройки агентов. Передать точный JSON frontend. Новая кнопка сохранения не требует нового API: существующий PUT уже подходит.

**Frontend Agent:** `frontend/`, HTML-шаблоны `backend/pages/`; не серверный Python. Публичная главная, modal auth с сохранением существующего API, локальные фоны и анимация, форма/pace-карточки, подключение каталога, мультивыбор обязательных мест, полное удаление автосохраняющих вызовов, понятный explicit-save/dirty-state. Ширины375 и1440, обе темы, клавиатура, Escape/focus, reduced-motion. Не создавать имитацию генерации. Кнопка сохранения не должна обещать построить маршрут.

**QA Agent:** применить `qa-integration-check` и независимо проверить:

1. Публичная главная доступна гостю; modal можно открыть/закрыть, выбрать login/register; правильные успешные маршруты после auth и ошибки без потери работоспособности.
2. Ввод в анкету + ожидание больше прежних800мс не вызывает PUT и не изменяет SQLite; уход не сохраняет. Только явная кнопка сохраняет. Открытие повторно восстанавливает последнюю сохранённую версию. Правки после клика не досылаются автоматически.
3. Несколько стран/городов и корректные зоны; старый Moscow draft; неверная тройка и ошибочное смещение отклоняются.
4. Валютный порядок, новая валюта из расширенного списка, отсутствие конверсии, строгая Decimal-сумма.
5. Несколько мест сохраняются; неверный/дублированный/чужой ID отклоняется; смена города не оставляет чужие места; источник каждого имени указан в данных.
6. Прежние owner-context/revision/Origin/session проверки не ослаблены; тема не вызывает сохранение.
7. Реальные браузерные desktop/mobile сценарии, темы и анимация. Если автоматизация не позволяет надёжно проверить узкую ширину, явно оставить ручную проверку открытой.
