## Исполнение настоящего JavaScript с контролируемыми DOM/fetch

Создан воспроизводимый `tests/fullstack/test_questionnaire_manual.cjs`. Он загружает **настоящий актуальный `frontend/questionnaire.js`** через node:vm, а каталог — из реального `frontend/assets/catalog.json`. Подставляются минимальные DOM и fetch с задержанным PUT; это тест логики клиента, не настоящий браузер/сеть. Зависимости не устанавливались.

Поскольку отдельный `node` CLI в текущей среде не гарантирован, тест фактически выполнен в доступном встроенном Node REPL через `createRequire(...)` и вызов экспортированной async-функции. При наличии CLI его можно повторить:

```sh
node tests/fullstack/test_questionnaire_manual.cjs
```

Фактический результат — PASS. Проверены:

- Загрузка сохранённой анкеты не делает PUT, восстанавливает Париж, GBP, состав и оба POI.
- Изменение бюджета не делает PUT и не ставит таймер скрытого автосохранения. Уход вызывает предупреждение, но не PUT.
- Один submit отправляет один снимок с исходной суммой125.50, revision7, schema0.2, timezone и старым owner-context.
- Пока PUT ожидает, правка до200.00 и повторный submit не запускают второй запрос. После ответа правка автоматически не досылается, редиректа нет, показано сообщение о несохранённых новых изменениях. Отправленный снимок остаётся125.50.
- Только второй отдельный submit отправляет200.00 с обновлённым revision8; после успеха выполняется переход в `/trips`.
- Старое московское aware-время schema0.1 и отсутствующий состав восстанавливаются без PUT.
- ACCOUNT_CHANGED409 не очищает поля и не перенаправляет, показывает ошибку.
- Отмена подтверждения смены страны/города сохраняет старые направление и POI. Подтверждённая смена очищает прежние POI и не сохраняет автоматически.

Native `checkValidity/reportValidity` в mock контролируемые; тест не доказывает реальное поведение календаря, клавиатуры, focus, layout или браузерных диалогов. Это проверяет координатор через CUA отдельно.

## Статическая интеграционная проверка

Frontend читает `/api/catalog` и использует те же `countries[].code`, `cities[].name/timezone/pois` и `currencies[].code/name`, по которым backend проверяет ввод. Новые запросы отправляют schema0.2 без UTC-смещения, legacy время снимается в локальные поля, жёсткий +03 удалён. Источник каждого имени POI есть в каталоге; это только локальные справочные ID, без координат, цен или обещания работы рекомендательного модуля.

Главная использует native `<dialog>` с `showModal()`, явным закрытием и возвратом фокуса к вызвавшей кнопке; Escape/удержание фокуса обеспечивает сам диалог браузера. Redirect задаётся локально `/trips` или `/trip/new`, внешнее значение из URL не используется. Скрытая форма не участвует в главной. Смена темы не вызывает отправку формы. Все страницы используют прежний theme.js. CSS содержит pause-кнопку анимации и отдельный reduced-motion режим.

Непроверенные этим агентом: настоящий браузерный focus/Escape, регистрация из modal, native поля, светлая/тёмная темы, визуальная адаптивность375/1440, плавность анимации и качество фотографий. Координатор ведёт настоящий браузерный сценарий на собственной временной БД; его результаты нужно читать отдельно.

## Ограничения и итог

Проверенная серверная и клиентская логика — **готова с ограничениями браузерной приёмки**. Полный MVP этим не подтверждён: нет реальной генерации маршрута, карты, Routing API/LLM и сопоставления локальных POI-ID с AI/DS. Каталог ограничен7 странами/8городами. Валюты не конвертируются, бюджет пока имеет общий технический предел2 знаков независимо от ISO minor_units.

Изменены QA: `test_travel_party.py`, новый `test_questionnaire_manual.cjs`, этот отчёт. TASKS.md, роли, чужие алгоритмы и конфигурации не изменялись.

## Финальная повторная проверка после динамического фона

После добавления `destination-visuals.js` повторно исполнены актуальные реальные JS-файлы. Первоначальный старый mock не загружал новый helper, поэтому тест остановился при восстановлении формы; это несоответствие fixture новой загрузке скриптов, не подтверждённая ошибка приложения. Fixture адресно расширена: исполняется настоящий `destination-visuals.js` перед `questionnaire.js`, добавлен только контролируемый `document.documentElement.style.setProperty` для оформления. Поведение сохранения и native validity не подменялось дополнительно.

Повторный результат **PASS**, включая прежние проверки ручного сохранения и confirm/cancel. Дополнительно проверено: Париж выбирает локальное `paris-sunset.jpg`, legacy Москва — `moscow-sunset.jpg`, сброс направления без города — нейтральный `travel-landscape.svg`. Имена города не используются как произвольные URL. HTML подключает helper перед анкетой через defer и содержит версии ресурсов для обновления старого браузерного кэша. Визуальную загрузку CSS и фото после cache-bust координатор проверяет настоящим браузером; этот тест проверяет выбор CSS-переменной, а не отрисовку.

HTTP-набор повторно не запускался: финальные изменения затрагивали только frontend и fixture JavaScript, новых серверных изменений для этой проверки не было.
