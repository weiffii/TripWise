## Независимый HTTP-прогон

```sh
NO_PROXY=127.0.0.1,localhost no_proxy=127.0.0.1,localhost .venv/bin/python -W error::ResourceWarning -m unittest discover -s tests/fullstack -v
```

**58/58 тестов прошли,34.213s, OK.** Использованы временные SQLite, вымышленные аккаунты и собственные свободные порты. Реальная база и сервер пользовательницы не читались и не останавливались. Это независимый полный прогон, отдельный от проверок разработчика.

Подтверждены:

- Две анкеты одного аккаунта получают разные id, остаются в списке, правка и удаление одной не меняют другую; состояние сохраняется после перезапуска.
- Повтор POST с тем же UUID/данными возвращает прежнюю карточку без дубля; иной payload под тем же ключом отклоняется409, служебный `legacy-v1` нельзя выдать за UUID нового клиента.
- Чужие GET/PUT/DELETE отвечают404, прежняя запись владельца не меняется. Анонимные list/read/create/edit/delete отклоняются401.
- Все записи защищены owner-context, Origin и revision; устаревшие PUT/DELETE не портят данные. Ответы private no-store,422 не раскрывает входные значения.
- Старая анкета мигрирует один раз с прежними параметрами/revision/timestamp; legacy API редактирует только её, а не новую соседнюю. Удалённая мигрированная карточка не воскресает после перезапуска, архив остаётся нетронутым.
- Три и все восемь основных интересов сохраняются/читаются, пустота/дубли/неизвестные значения/secondary overlap отвергаются.
- Прежние регрессии аккаунтов, смены владельца старой формы, DST, каталога, POI, Decimal, валют и состава компании продолжают проходить.

## Настоящий JavaScript с mock DOM/fetch

Расширен воспроизводимый `tests/fullstack/test_questionnaire_manual.cjs`. Фактически выполнен через доступный Node REPL (`createRequire` → экспортированная async-функция); при наличии Node CLI повторяется командой:

```sh
node tests/fullstack/test_questionnaire_manual.cjs
```

Исполняются реальные текущие `questionnaire.js`, `destination-visuals.js` и `trips.js`; DOM/fetch/ответы подставлены для детерминированной проверки. **PASS** после финальной правки. Сетевые запросы в этом тесте не настоящие; native browser validity/focus/layout не проверяются.

Сценарии:

- Загрузка, input и beforeunload не отправляют POST/PUT и не ставят таймер скрытого автосохранения. Уход с изменениями вызывает предупреждение.
- Редактирование `/trip/new?id=11` отправляет PUT именно `/api/trips/11` с revision/owner. Снимок на момент клика неизменен; правка во время ожидания не досылается, повторный click во время запроса не дублирует сохранение. После ответа новые изменения остаются на странице до отдельного клика.
- Новая форма не подставляет последнюю сохранённую поездку и не создаёт запись при открытии. Первый явный click отправляет POST с UUID без revision. При изменениях во время POST после успеха запоминается новый id; следующий явный click — PUT именно нового id с revision1, не ещё один POST.
- Все восемь основных интересов остаются включёнными и отправляются без усечения.
- После определённого422 исправленная сумма555 попадает в новую попытку. После неопределённого результата POST повторяется прежний **точный body/UUID**, а новая локальная сумма777 остаётся несохранённой до следующего явного действия; скрытого PUT нет.
- Старая московская анкета и состав восстанавливаются, корректный локальный фон выбирается. Confirm/cancel смены страны/города сохраняет либо явно очищает POI, не пишет на сервер.
- Карточки имеют Edit со своим id. Отмена Delete не отправляет запрос. Ошибка Delete оставляет карточку и показывает ошибку. Успешное удаление отправляет id/revision/owner и убирает только выбранную карточку.

## Найденная проблема и повторная проверка

QA статически обнаружил P1: новый `unresolvedCreation` оставался зафиксированным и после HTTP422. Если пользователь исправлял данные, следующий click повторял старый невалидный payload. Проблема фактически передана координатору и frontend исполнителю. Исполнитель сбросил снимок при определённых400/422, сохранив его для неопределённых сетевых результатов. QA добавил и исполнил регрессии **422→исправление→новый body** и **потерянный ответ→прежний body/UUID** — PASS. До исправления проблема не воспроизводилась исполнением, поэтому «падавший до фикса тест» не заявляется.
