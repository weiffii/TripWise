# Объединение Fullstack и маршрутизатора: backend

Дата: 22 ноября 2026. Ветка: `feature/fullstack-unified`; согласованное объединение исходных `integration/fullstack-ai-ds` и `feature/fullstack`. Backend-исполнитель работает параллельно с frontend и не меняет алгоритмы `ai_ds/`.

## Реализованный сценарий

1. `POST /api/route-previews` принимает `{form_preferences, source_preview_id?}` и `X-TripWise-Draft-Owner`. Применяет отдельный адаптер анкеты к реальным `MoscowPreferences`/`ShanghaiPreferences` и вызывает существующие генераторы через `build_plan`. Новая поездка в SQLite здесь не создаётся.
2. `GET /api/route-previews/{id}` возвращает тот же формат плана, который использует имеющийся экран расписания/карты, с `preview_id`, `is_preview`, `form_preferences`, `owner_context`.
3. Только `POST /api/route-previews/{id}/save` с `{version}` сохраняет серверный доверенный план в `planned_trips`. Клиент не присылает произвольное содержимое маршрута для записи. Повтор Save возвращает ту же запись.
4. `POST /api/planned-trips/{id}/preview` с `{version}` создаёт редактируемую копию сохранённого маршрута в памяти. Последующее Save обновляет только исходный ID с проверкой исходной версии; исходная запись до Save не меняется.
5. `DELETE /api/planned-trips/{id}` принимает `{version}` и контекст владельца; чужой ID даёт404, изменённая версия409. Старые сохранённые анкеты `/api/trips` остаются отдельными сущностями.

Все новые записи/удаления защищены сеансом, Origin, исходным контекстом владельца и принадлежностью строки. Предпросмотр дополнительно привязан к хешу конкретного сеанса, а не только аккаунту. Выход/повторный вход не даёт читать прежний предпросмотр. Кэш действует60мин, ограничен128записями и теряется при перезапуске; это явно временный предпросмотр, не сохранённая поездка.

## Сохранение существующей логики

`backend/shanghai.py` разделяет построение и старое сохранение: `build_plan` вызывает прежние функции Москвы/Шанхая; старый `POST /api/planned-trips` оставлен для совместимости и по-прежнему сохраняет сразу. Новый интерфейс его не использует. Просмотр сохранённых маршрутов доступен даже если отдельные старые параметры ещё не представлены новой анкетой.

Пути помощника `/api/route-previews/{id}/assistant/status` и `/{register|message|decide}` используют прежнюю проверку CSRF и регистрацию. Подтверждение предложения и история диалога для предпросмотра меняются только в памяти; SQL-ветка старого помощника не выполняется. Новый интерфейс сначала создаёт копию сохранённого маршрута для правок. Алгоритмы, коэффициенты и данные напарника не менялись.

## Адаптер и фактические ограничения

- Доступны только RU/Москва/Europe/Moscow и CN/Шанхай/Asia/Shanghai. Россия и Китай первые в справочнике; остальные направления отключены в новом интерфейсе и отвергаются генерацией.
- Москва поддерживает RUB; Шанхай RUB/USD/EUR/CNY. Расчётный фиксированный FX из исходного генератора сохранён, не объявляется текущим банковским курсом. Новые валютные API не подключались.
- Поездка1–5календарныхдней. В каждой возрастной группе максимум30человек. Все восемь интересов и все выбранные способы передвижения передаются без молчаливого усечения.
- Промежуточные дни09:00–21:00, первый начинается точно в указанное время, последний заканчивается точно в указанное время. Каждый дневной интервал минимум60мин; несовместимые окна отвергаются422.
- `walking`→`walk`, `public_transit`→`transit`, `car`→`taxi` — существующая модель расходов такси, не обещание расчёта личного автомобиля.
- Обязательные места берутся по настоящим ID из `/api/planned-trips/catalog/{city}`. Локальные демонстрационные ID прежней анкеты не подменяются идентификаторами генератора.

## Файлы

`backend/main.py` — ручное разрешение конфликта с подключением всех router, защитой result и no-store приватных API; `backend/route_previews.py` — адаптер, кэш, Save/fork/delete; `backend/shanghai.py` — общий построитель и ветка памяти для помощника; `backend/drafts.py` — контекстная проверка реальных POI только для генерации; `frontend/assets/catalog.json` — активность Москвы/Шанхая и порядок стран. Новых зависимостей нет.

## Проверки исполнителя

`py_compile` четырёх затронутых Python-модулей и `git diff --check` по своим файлам прошли. Новый `tests/fullstack/test_route_preview.py` исполняет настоящие HTTP-запросы на временной SQLite и собственном порту; генератор для контрактных тестов заменён явно синтетическим контролируемым ответом. Проверены отсутствие записи доSave, идемпотентностьSave, две независимые поездки, редактирование копии, конфликт версий, удаление, привязка к сеансу, чужие ID, Origin, owner-context, ограничения адаптера и передача всех интересов. Отдельно проверены истечение кэша и отсутствие SQL при подтверждённой правке/истории в памяти.

Первый запуск HTTP был заблокирован sandbox на socket.bind; разрешённый повтор выполнен на временном порту. Реальная генерация маршрутов, карта и живой помощник переданы координатору/независимому QA; контролируемый генератор этих тестов не доказывает их работу. Пользовательская база и сервер исполнителем не читались и не менялись; git stage/commit/push не выполнялись.

Для объяснения: генератор создаёт временный объект, а Save записывает его в SQLite. Вопрос на понимание: почему закрытие вкладки доSave не должно добавлять карточку в «Мои поездки»?
