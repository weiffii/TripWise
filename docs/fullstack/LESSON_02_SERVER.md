# Второе занятие Первый сервер TripWise

Дата: 17 ноября 2026 года. Ветка: feature/fullstack. Новые файлы: backend/__init__.py, backend/main.py, requirements.txt, .gitignore, README.md и этот отчёт. Изменён статус первого среза в BACKEND_FIRST_SLICE.md. Участница разрешила продолжить после предложения установить FastAPI и Uvicorn.

## Результат

В проекте создано отдельное окружение .venv, установлены FastAPI 0.163.1 и Uvicorn 0.54.0 вместе с зависимостями. Версии всех установленных библиотек зафиксированы в requirements.txt. Системное окружение Python не изменялось. Пакеты скачаны из Python Package Index. Дополнительные зависимости хеширования паролей и базы не устанавливались.

Сервер открывает существующий frontend и отвечает на GET /api/health. Данные формы по-прежнему не отправляются на сервер. Пользователей, БД, сеансов входа и доступа к «Моим поездкам» ещё нет. Полный сервис и модель напарника не запускались.

## Простое объяснение

Браузер просит: «Дай содержимое адреса /api/health». Сервер вызывает Python-функцию health. Она возвращает словарь, а FastAPI превращает его в JSON-ответ:

```json
{"status":"ok","service":"TripWise"}
```

GET означает запрос на чтение. /api/health — путь запроса. @app.get связывает путь с функцией. return возвращает результат. Это пока только подтверждение запуска приложения; база и внешние API такой проверкой не проверяются.

app.mount выдаёт файлы из frontend при запросах страницы, стилей и JavaScript. Весь проект не выставляется в браузер. Путь к frontend вычисляется от расположения backend/main.py, а не случайной текущей папки. API объявлен до подключения файлов, чтобы обработчик файлов не перехватывал /api/health.

## Фактические проверки

Сервер запускался через .venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8765. Проверки выполнялись по настоящему локальному HTTP, через urllib стандартного Python. Отдельные библиотеки тестирования не добавлялись.

| Запрос | Фактический результат |
|---|---|
| GET / | 200, точное содержимое frontend/index.html |
| GET /index.html | 200, тот же HTML |
| GET /styles.css | 200, точное содержимое frontend/styles.css |
| GET /auth.js | 200, точное содержимое frontend/auth.js |
| GET /api/health | 200, ожидаемый JSON |
| GET /openapi.json | 200, описан /api/health |
| GET /docs | 200, страница документации |
| GET /api/missing | 404 |
| GET /backend/main.py | 404 |
| GET /.git/config | 404 |
| GET /../backend/main.py | 404 |
| POST /api/health | 405 |

Итого: 12 HTTP-проверок прошли. Отдельно pip check сообщил No broken requirements found. git check-ignore подтвердил исключение .venv/bin/python, runtime/tripwise.sqlite3 и .env. Эти последние пути проверены как правила исключения; база и .env не создавались. Остановка Uvicorn выполнена после проверки, чтобы участница могла сама запустить сервер без конфликта порта.

Внутренние пути проверялись на указанных примерах, а не исчерпывающим аудитом безопасности. GET /docs проверяет выдачу HTML; загрузка внешних ресурсов Swagger UI в браузере отдельно не проверена. При недоступном интернете интерактивная документация может зависеть от CDN; /api/health и основной frontend от него не зависят.

## Практика на Mac

В терминале VS Code из корня проекта выполнить:

```sh
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8765
```

- .venv/bin/python — Python именно этого проекта.
- -m uvicorn — запуск установленного модуля Uvicorn.
- backend.main:app — файл backend/main.py и объект app внутри него.
- --host 127.0.0.1 — доступ только на этом компьютере.
- --port 8765 — номер порта.

Оставить терминал работающим. Открыть http://127.0.0.1:8765/api/health и увидеть JSON. Открыть http://127.0.0.1:8765/ и увидеть форму. Вернуться в терминал, нажать Control+C и обновить страницу /api/health: новый запрос не должен получить ответ от остановленного сервера. При необходимости запустить повторно той же командой.

Вопрос: при открытии /api/health какая часть формирует JSON-ответ — JavaScript страницы или Python на сервере?

## Следующее занятие

Реальная регистрация: серверная проверка, SQLite и безопасное хранение паролей. Не принимать наличие страницы регистрации или адреса /api/health за готовый аккаунт. До этого этапа убедиться, что участница самостоятельно запустила сервер и поняла запрос/ответ. Изменения пока не закоммичены и не отправлены на GitHub.
