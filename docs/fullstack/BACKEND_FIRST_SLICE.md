# Следующий срез регистрации и входа

Статус на 17 ноября 2026 года: первый сервер, регистрация, вход/выход, SQLite-аккаунты и защищённый раздел «Мои поездки» реализованы и проверены. Создание поездок ещё не реализовано. Ответственный: Участник 2. AI/DS напарника не изменяется. Фактические отчёты: LESSON_02_SERVER.md и LESSON_03_ACCOUNTS.md.

## Зачем нужен сервер

Сейчас браузер лишь проверяет заполнение полей. Для настоящего аккаунта сервер должен независимо проверить ввод, сохранить пользователя в базе и узнавать его при последующих запросах. После входа пользователь попадает в «Мои поездки».

## Предлагаемая основа

- FastAPI — Python-библиотека для обработки запросов браузера.
- Uvicorn — программа, запускающая приложение FastAPI.
- SQLite — база, доступная через стандартный Python-модуль sqlite3; отдельная установка сервера БД не нужна.
- Изолированное окружение .venv внутри проекта — зависимости относятся к TripWise, а не устанавливаются глобально.

Первые две библиотеки и создание окружения согласованы и установлены. Версии зафиксированы в requirements.txt. Дополнительные библиотеки для обработки паролей определить и согласовать перед установкой по актуальной официальной документации. Не считать две названные библиотеки окончательным полным списком зависимостей аутентификации.

## Порядок небольших шагов

1. Запуск сервера и проверка доступности. Браузер получает текущий интерфейс с того же адреса; проверочный запрос возвращает JSON. Учебная задача: запустить и остановить сервер самостоятельно.
2. Реальная регистрация: обязательные поля, повторная серверная проверка, уникальная почта, безопасное хранение пароля. Пароль хранится как результат специального алгоритма хеширования с солью, а не как исходный текст. База и секреты исключаются из Git.
3. Реальный вход: проверка пароля, серверный сеанс с ограниченным сроком, cookie HttpOnly и выход с завершением сеанса. Настройки cookie для HTTPS и локального запуска различаются. До подключения не имитировать вход через localStorage.
4. Защищённая страница «Мои поездки»: без входа недоступна; новый аккаунт видит пустое состояние. Чужие поездки недоступны. Создание маршрута и интеграция AI/DS идут отдельным этапом.

Созданы backend/, README.md и tests/fullstack/test_accounts.py. Реализованы GET /api/health и API /api/auth/; контракт AI/DS не меняется. Первый шаг сервера проверен отдельно; следующий шаг аккаунтов прошёл 13 интеграционных тестов и проверку в браузере. Дополнительные внешние библиотеки для аккаунтов не понадобились: SQLite, scrypt и создание случайных токенов доступны в Python.

## Проверки по мере реализации

Запуск/остановка, выдача HTML/CSS/JS, понятная ошибка недоступного сервера; затем корректная регистрация, повторная почта, некорректные данные, неверный пароль, вход/выход, отказ без сеанса и изоляция двух пользователей. Проверять сохранение аккаунта после перезапуска. Реальное восстановление пароля и подтверждение почты ещё не обсуждались; не добавлять неработающие кнопки и не заявлять проверку владения почтой.
