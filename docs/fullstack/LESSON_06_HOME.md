# Занятие 6. Главная, модальное окно и сохранение по кнопке

Дата: 21 ноября 2026. Новый запрос Участника 2 заменил прежние решения «сначала вход», «только Москва» и «автосохранение анкеты». История предыдущих занятий сохраняется; текущее поведение описано здесь и в README.

## Что теперь работает

Главная доступна без аккаунта и объясняет TripWise. Верхние кнопки открывают вход или регистрацию в модальном окне. «Создать поездку» для гостя открывает регистрацию; после успешного действия из этой кнопки пользователь попадает прямо в анкету. Для уже вошедшего пользователя создание поездки открывает анкету без регистрации. Обычный вход из шапки ведёт к «Моим поездкам».

На главной плавно меняются локальные фотографии Москвы, Парижа и Стамбула. Это анимация фотографий, не видео; предусмотрены пауза и reduced-motion. `destination-visuals.js` подбирает фон к направлению, для города без подходящего фото используется нейтральная авторская иллюстрация. Три карточки темпа получили SVG-иллюстрации, значения relaxed/balanced/intensive сохранены. Светлая и тёмная темы запоминаются.

Справочник содержит 7 стран / 8 городов: Москва, Санкт-Петербург, Париж, Рим, Стамбул, Токио, Пекин, Лондон. В каждом по 2 обязательных места, всего 16; их можно выбрать вместе, искать и убирать по отдельности. Источник названия каждого места указан в source_url. Локальные ID вида `local:paris:eiffel-tower` не выдаются за OSM или ID напарника. Это небольшая подборка названий, не полное покрытие мира и не POI-набор рекомендательного алгоритма.

Валют 155: RUB/USD/EUR/CNY первыми, остальные по коду. Backend использует локальный снимок официального SIX с исключением специальных/фондовых записей. Новые библиотеки и обменные курсы не добавлены. Сумма сохраняется в исходной выбранной валюте; предел двух знаков после запятой остаётся техническим правилом бюджетной анкеты независимо от minor_units. Скидок и платежей нет.

## Чем кнопка отличается от автосохранения

Теперь ввод, выбор города, поиск места, ожидание и уход со страницы **не вызывают PUT**. Поля остаются в памяти вкладки до «Сохранить анкету». Это прямое выполнение нового пожелания.

По кнопке questionnaire.js делает снимок полей и отправляет один PUT. Повторный клик во время запроса не создаёт второй запрос. Если во время ожидания пользователь изменил поля, отправленный снимок остаётся прежним, а новые значения требуют отдельного нажатия. Ошибка оставляет поля на странице; при уходе браузер предупреждает о несохранённых правках.

Backend повторно проверяет JSON и сохраняет его в SQLite только по принятому PUT. GET читает прежние значения. После успешного сохранения открывается карточка **анкеты**; повторное открытие показывает последнюю явно сохранённую версию. Называть её готовым маршрутом пока нельзя: генерация не подключена.

## Каталог и версия 0.2 простыми словами

`frontend/assets/catalog.json` — единый список допустимых вариантов. Backend читает и проверяет его; GET `/api/catalog` возвращает интерфейсу, `/api/travel-catalog` является alias. Браузер предлагает те же города, валюты и места, которые разрешает сервер. Серверная проверка нужна даже при правильной форме: запрос можно отправить вручную.

Новая схема `fullstack-draft-0.2` отправляет местные ISO даты/время без UTC-смещения и IANA timezone выбранного города. Например, Париж — Europe/Paris. Сервер проверяет связанную тройку страна/город/зона и отклоняет час, пропущенный или повторённый при сезонном переводе. Нельзя приклеить ко всем городам московское +03:00 или часовой пояс ноутбука.

Старая московская схема 0.1 с явным смещением поддерживается; GET не переписывает БД/revision. Для старого отсутствующего состава возвращается техническое «все взрослые». Сохранены Origin, сеанс, исходный owner-context и revision: старая вкладка одного аккаунта не перезаписывает другой аккаунт.

## Что действительно проверено

Отдельный QA применил qa-integration-check и запустил **46 HTTP-тестов**, результат OK за 24.466 с, без ResourceWarning. Использовались временные БД и собственные порты. Проверены справочник, валюты, направления, несколько мест, неверные связи город/POI/зона, DST, Decimal, состав, старые данные, владельцы, версии и аккаунты.

QA также реально исполнил актуальный JS через Node VM с контролируемыми DOM/fetch — PASS. `tests/fullstack/test_questionnaire_manual.cjs` проверяет отсутствие скрытого PUT при вводе и уходе, снимок на кнопку, отсутствие автоматической досылки новых правок, повторное явное сохранение и защиту смены аккаунта. Native-календарь, focus и внешний вид этим тестом не доказываются. После финальных изменений помощника визуализации и ручного сохранения QA повторил проверку — PASS.

Координатор отдельно в настоящем браузере выполнил: «Создать поездку» → регистрационное окно → Escape и возврат фокуса → регистрация вымышленного аккаунта → `/trip/new` → Париж, EUR 500 и два обязательных места. До сохранения поездки во второй вкладке оставались пустыми. После «Сохранить анкету» появилась карточка; повторное открытие восстановило два места.

В финальной браузерной проверке устаревший CSS в кэше устранён версией в query строки ресурса; после reload главная отобразилась полностью оформленной. Координатор реально наблюдал смену фотографии Парижа на Стамбул. В анкете Парижа проверены соответствующая CSS-переменная фона и три иллюстрации темпа. При ширине 375 получен надёжный снимок, scrollWidth=375 совпал с viewport 375, нажатие темы реально переключило DOM на dark. После проверки исходный viewport восстановлен. Это закрывает прежнюю неопределённость адресной проверки 375; полного тестирования всех устройств не заявляем.

QA обнаружил очистку выбранных мест при смене города без предупреждения. Frontend Agent добавил подтверждение; QA повторно проверил confirm/cancel — PASS. Этот дефект и повторная проверка не являются вымышленным пользовательским интервью.

## Практика

Войдите в учебный аккаунт, измените анкету, не сохраняйте, сравните прежние поездки во второй вкладке. Затем явно сохраните, откройте анкету повторно и проверьте город, валюту и два места.
