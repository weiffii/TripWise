# Первое занятие по Git

## Понятие ветки

Репозиторий — папка проекта с историей сохранённых изменений. Коммит — сохранённый этап. Ветка — имя линии разработки: ты и напарник можете независимо сохранять свою работу и позже сравнивать изменения через Pull Request. До объединения ваши файлы могут отличаться.

main — общая линия; feature/ai-ds — линия напарника; feature/fullstack — твоя новая линия. origin — короткое имя GitHub-адреса. origin/feature/ai-ds — локальное представление опубликованной ветки после последнего получения данных. Ветка сама по себе не создаёт отдельную папку; переключение меняет содержимое текущей рабочей папки.

## Уже выполненные Git-команды

| Команда | Что означает |
|---|---|
| git clone https://github.com/weiffii/TripWise.git . | clone скачивает существующий репозиторий, точка задаёт текущую пустую папку |
| git status --short --branch | status показывает состояние; --short сокращает вывод; --branch показывает ветку |
| git log -5 --oneline | log показывает коммиты; -5 ограничивает число; --oneline выводит строку на коммит |
| git log --all --oneline --decorate -10 | --all включает другие локально известные ветки; --decorate подписывает имена; -10 ограничивает список |
| git branch -a | branch перечисляет ветки; -a включает локальные представления удалённых |
| git ls-tree -r --name-only HEAD | ls-tree читает дерево коммита; -r идёт по подпапкам; --name-only показывает имена; HEAD означает текущий коммит |
| git ls-tree -r --name-only origin/feature/ai-ds | Аналогичный список из ветки напарника без переключения на неё |
| git show origin/feature/ai-ds:путь | show читает файл на выбранной версии; двоеточие отделяет версию от пути |
| git archive origin/feature/ai-ds | Получает снимок файлов ветки; для проверки он распакован во временную папку, а не поверх проекта |
| git switch -c feature/fullstack | switch переключает ветку; -c сначала создаёт её с указанным именем |

## Маленькая практика сейчас

Открой папку проекта в VS Code через «Файл → Открыть папку», затем «Терминал → Новый терминал». Так терминал обычно сразу открывается в папке проекта. Проверь:

```sh
pwd
git branch --show-current
git status --short
```

pwd печатает путь текущей папки. git branch --show-current печатает только имя выбранной ветки. git status --short показывает изменённые и новые файлы. Ожидаем feature/fullstack и новые документы docs/fullstack/. Префикс ?? означает: файл ещё не добавлен в историю Git. Это нормально, файлы уже сохранены на диске.

Пришли вывод этих трёх команд. Вопрос для понимания: почему код ai_ds есть на GitHub в ветке напарника, но сейчас отсутствует в твоей папке?

## Следующее занятие — сохранение и Pull Request

Ниже памятка, а не уже выполненные действия. Сначала просмотрим документы и научимся сохранять маленький этап.

```sh
git add docs/fullstack
git diff --cached
git commit -m "docs: add fullstack starting audit and plan"
git push -u origin feature/fullstack
```

add выбирает файлы для ближайшего коммита. diff --cached показывает выбранные изменения до сохранения. commit создаёт этап истории; -m задаёт его сообщение. push отправляет локальные коммиты на GitHub; -u связывает твою ветку с origin/feature/fullstack для следующих отправок. Для push нужен доступ на запись в общий репозиторий; он пока не проверялся.

На GitHub Pull Request сравнивает base: main и compare: feature/fullstack. Мы покажем различия и попросим напарника проверить. Merge выполняем после проверки и согласования. Секреты API и локальную базу не добавляем в коммит.

## Получение изменений напарника

```sh
git status
git fetch origin
git log --oneline HEAD..origin/main
git diff HEAD...origin/main
```

status проверяет локальные изменения. fetch получает опубликованные коммиты, не меняя текущие рабочие файлы. log HEAD..origin/main показывает коммиты общей ветки, которых нет в текущей. diff с тремя точками показывает изменения main от общей точки ветвления.

После сохранения своей работы, ревью и согласования можно выполнить git merge origin/main прямо в feature/fullstack. merge объединяет общую версию с твоей, сохраняя историю. Конфликты требуют осмысленного разбора; не выбирать автоматически всю свою или чужую версию. Если напарник ещё не объединил AI/DS в main, fetch сам по себе не перенесёт ai_ds в твою ветку. Прямое объединение его feature-ветки нужно согласовать отдельно.
