# Задание для продолжения Fullstack

## Подготовка

Основной инструмент сейчас — уже работающий в этом проекте Codex; новую установку не требуем. В этом чате подтверждены чтение проекта, выполнение команд, создание ветки и проверка тестов. Доступ к платным API или безлимитная работа не предполагаются.

У проекта уже есть AGENTS.md, шесть скиллов в .agents/skills/ и шесть конфигураций в .codex/agents/. Frontend и backend как отдельные зарегистрированные роли отсутствуют. Чужие конфигурации не переписывались. Их автоматическое обнаружение и отдельный запуск в новом сеансе не подтверждены. Собственный fullstack-скилл создадим на основе повторяемой реальной задачи, после того как станет понятен её процесс.

В текущем анализе прочитан и применён процесс .agents/skills/analyst-requirements/SKILL.md: сопоставление требований с кодом, выделение неизвестных, разделение задач и подготовка этого задания. Это ручное чтение инструкции и применение процесса в основном чате; не доказательство автоматического обнаружения или отдельного вызова Analyst Agent. Передачи между отдельными агентами и стороннего MCP ещё не было.

AGENTS.md задаёт постоянные инструкции проекта, SKILL.md — повторяемый рабочий процесс. Официальные пояснения: https://learn.chatgpt.com/docs/agent-configuration/agents-md и https://learn.chatgpt.com/docs/customization/overview . Наличие конфигурационного файла не заменяет фактическую проверку доступности инструментов.

## Готовое следующее задание

Ты помогаешь Участнику 2 TripWise, начинающей студентке на Mac. Объясняй небольшими шагами, давай одну практику и вопрос на понимание. Сначала прочитай AGENTS.md, docs/fullstack/START_REPORT_2026-11-17.md и актуальные требования docs/. Проверь git status и текущую ветку: работаем только в feature/fullstack. Не считай подготовленный план готовым продуктом.

Цель следующего этапа: согласовать первый небольшой срез «анкета → сервер → явно демонстрационный JSON-ответ». Сначала объясни, как браузер посылает запрос и сервер отвечает, на примере TripWise. После понимания согласуй предложенный стек Python/FastAPI, SQLite и HTML/CSS/JS. Не устанавливай зависимости до согласования.

Контракт напарника изучать из его опубликованной ветки: docs/ai/contracts-v0.1.md и docs/ai/routing-contract-v0.1.md. При обновлении ветки повторно проверить отличие от 7aa6746. Первый сервер должен оборачивать его публичные функции после проверенной интеграции; не копировать и не переизобретать алгоритмы. Не принимать многодневность baseline за реализованную. Если модуль пока недоступен в main, явно показывать демонстрационное состояние; не выдавать заглушку за персональный маршрут.

На проектировании сначала описать минимальный запрос анкеты, ответ, ошибки и границы хранения; предложенные HTTP-пути пока не утверждены. После согласования реализации работать только в новых fullstack-файлах; пути выбрать и записать в задании перед созданием. Общие контракты, ai_ds/, чужие tests/, AGENTS.md и настройки напарника не менять без обсуждения.

Критерии первой реализации: понятная форма, отправка на локальный сервер, видимый ответ, понятная ошибка невалидного ввода, воспроизводимая инструкция запуска. Не подключать карту, LLM и Premium в той же учебной задаче. Проверить успешный и ошибочный запрос; затем объяснить основные функции и дать участнице самостоятельно повторить запуск.

После реализации подготовить отдельное задание роли проверки с требованиями и шагами воспроизведения. Не заявлять независимую проверку, пока другой исполнитель действительно её не выполнил. В отчёте указать файлы, команды, фактический результат и ограничения. Следующий этап после этого среза — интеграция AI/DS и сохранение.
