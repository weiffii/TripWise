# Подключение Москвы к TripWise: анализ совместимости

**Алгоритм и данные Шанхая не менялись.** Проверялся действующий `ai_ds/web_demo/shanghai-engine.js` из ветки `feature/ai-ds` проекта [weiffii/TripWise](https://github.com/weiffii/TripWise/tree/feature/ai-ds).

## Файлы

- `pois_real_master.json`: каноническая реальная база (1 268 POI). Неизвестные поля представлены `null` / `unknown`.
- `pois_tripwise_demo.json`: **предпросмотровая** проекция из 1 224 записей B, но не рабочий прямой вход текущего Shanghai Engine.
- `config.json`: Москва, Europe/Moscow, RUB, `ru-RU`.
- `pois.csv` / `pois.geojson`: экспорт для аналитики, GIS и отображения.

## Несовместимости текущего движка

| Требование `shanghai-engine.js` | Московский каталог | Что нужно изменить позже |
|---|---|---|
| Координаты в диапазоне широты 30–32, долготы 120–123 | Москва около 55–56, 37–38 | Вынести в городскую конфигурацию; координатная валидация по региону |
| Цена в CNY, бюджет `budget_cny`, `price_cny` / `avg_check_cny` | Неизвестные цены, валюта RUB | Обобщить валюту, конвертацию и обработку неизвестной цены без фиктивных нулей |
| Для каждого POI обязателен `opening` с `closed_weekdays` | Часы неизвестны | Ввести явное состояние расписания `unknown` и осторожные ограничения доступности |
| `duration_minutes`, `rating`, семейные/возрастные/питомцы, число отзывов | Большинство не известно | Отдельный документированный слой допущений `estimated`, без перезаписи фактов |
| `kind`: `attraction` или `restaurant` | Пока все `attraction`, кафе отсутствуют | Добавить реальные рестораны из актуального источника |
| Транспортная оценка и дорожная матрица | Дорожный доступ не подтверждён; координаты входов отсутствуют | Проверять вход и дорожную привязку, не заменять исходные координаты |

**Нельзя** подавать этот файл в текущий Shanghai Engine: он отклонит координаты/часы либо некорректно обработает цены. Чтобы удовлетворить его ограничения без изменений кода, пришлось бы придумывать поля; здесь этого не сделано.

## Следующие приоритеты

1. Получить прямой московский OSM PBF по административным границам, включая ТиНАО; извлечь фактические `osm_id` и все восемь интересов, особенно места питания.
2. Дополнить Overture/официальными каталогами с проверкой совместимости лицензий и устойчивой дедупликацией.
3. Ввести отличные друг от друга `poi_centroid`, `entrance_point` и `routing_snap_point` с документированной геометрией.
4. После фиксации данных изменять маршрутизатор **в отдельной задаче**, обеспечив отказоустойчивое обращение с неизвестными часами/ценами/длительностями.
5. Нагрузочные испытания 5 000 синтетических POI Шанхая оставить отдельно от испытания достоверности Москвы.
